# 无线通信 SoC 集合设计 —— 项目目标与范围（v0.1）

> 日期：2026-09-24
> 定位：数字 IC 设计学员的系统性练手项目，以数字基带与数字实现为主战场。

---

## 1. 一句话定位

从「比特流 → 射频波形 → 比特流」的完整链路视角出发，**由数字 IC 设计学员主导数字侧（调制解调、信道编码、同步、数字中频、数字接口）的设计与 RTL 实现**，射频/天线/协议栈作为协作接口与边界条件，不做深入实现。

选择这个定位的原因：

- 数字 IC 是本人的核心技能与职业方向，项目应服务于它（RTL、验证、综合、时序、低功耗），而不是让项目变成射频工程练习；
- 无线通信恰好是数字 IC 设计最有代表性的应用域之一：算法（DSP）→ 架构 → RTL → 物理实现的链条完整；
- 全栈视角保证设计出来的数字电路"知道自己在系统里干什么"，接口定义清晰，不被纸面规格架空。

## 2. 系统全景与分工边界

```
┌────────────┐   ┌─────────────┐   ┌──────────────┐   ┌────────────┐   ┌────────────┐
│  应用/协议层 │ → │  MAC/链路层  │ → │   数字基带    │ → │  数据转换器   │ → │  射频前端   │
│ (协作,浅做) │   │ (协作,浅做)  │   │ ★ 主战场     │   │ (接口建模)   │   │ (协作边界)  │
└────────────┘   └─────────────┘   └──────────────┘   └────────────┘   └────────────┘
                                       ▲                                      │
                                       └────────── 天线/信道（协作，模型级）──────┘
```

| 领域 | 角色 | 投入深度 |
|---|---|---|
| 数字调制/解调、同步、均衡 | **主导实现** | 算法建模 → 定点化 → RTL → 验证 → 综合 |
| 信道编码（FEC：卷积/LDPC/Polar） | **主导实现** | 同上 |
| 数字中频、DDC/DUC、采样率转换（CIC/FIR） | **主导实现** | 同上 |
| 数字电路设计（微架构、总线、控制 FSM、低功耗） | **主导实现** | 项目工程化主体 |
| ADC/DAC 接口、数字校准逻辑 | 主导（接口侧） | RTL + 行为级模型对接 |
| 射频电路（LNA/PA/混频器/PLL） | 协作边界 | 只写规格与接口，提供 SPICE 级行为模型用于系统仿真 |
| 天线 | 协作边界 | 提供方向图/S 参数等效模型，不做电磁仿真 |
| 网络/协议栈 | 协作内容 | 只做足够支撑基带验证的最小帧结构 / 状态机 |
| 信道模型 | 半主导 | AWGN/瑞利/多径 + 相位噪声/频偏/ CFO 等损伤模型（建模用 Python/MATLAB） |

## 3. 主要交付物

按类型列出，标注优先级（P0 = 第一阶段必做）：

1. **文档**
   - 系统规格书（频段、带宽、调制方式、数据率、链路预算的定性结论）（P0）
   - 算法方案与定点化报告（P0）
   - 微架构设计文档（模块划分、接口协议、时钟/复位域、低功耗策略）（P0）
   - 验证计划（testplan、覆盖率目标）（P1）
2. **Verilog/SV RTL**（P0 起持续产出）
   - 调制解调器核心：BPSK/QPSK/16QAM 映射与解映射（P0）
   - 帧同步 / 载波同步（频偏估计纠正） / 定时同步（P1）
   - FEC 编解码器：卷积码（Viterbi）起步（P1），LDPC/Polar 视进度（P2）
   - DDC/DUC、CIC + 补偿 FIR（P1）
   - 顶层集成：AXI-Stream 风格数据通路 + 控制寄存器接口（P1）
3. **SPICE / 电路级**
   - 非主导：仅在需要接口行为时写简化模型（如 ADC 量化噪声的等效、比较器行为级 SPICE），不为 RF 晶体管电路负责
4. **算法/系统模型**
   - Python（NumPy/Matplotlib）链路级仿真：调制、信道、同步、误码率曲线（P0）
   - 定点模型与 RTL 的 bit-true 对比环境（P1）
   - 天线/射频的等效模型文件（S 参数或方向图插值表）（P2，协作提供）
5. **验证环境**
   - SystemVerilog testbench + 断言 + 覆盖率（P1）
   - 与 Python 模型的协同仿真比对（如通过文件/DPI）（P2）
6. **网络层（最小化）**
   - 自定义极简帧格式 + CRC + ARQ 状态机，仅用于端到端演示（P2）

## 4. 建议技术路线（目标系统）

为让项目收敛，建议锁定一个具体目标制式作为载体（可讨论调整）：

- **候选：IEEE 802.15.4（Zigbee 物理层）类或自定义短距低速系统**
  - 理由：带宽窄（2 MHz 级）、调制简单（O-QPSK）、同步要求中等、编码经典（卷积码），适合手工 RTL 练级；
  - 数据率 250 kbps 量级，时钟频率 16–32 MHz 级，FPGA/综合都轻松；
  - 若嫌简单，备选 OFDM 子集（如简化 802.11a 单天线模式）作为第二阶段升级。

## 5. 分阶段路线图

| 阶段 | 内容 | 出口标准 |
|---|---|---|
| **Phase 0：准备**（约 1–2 周） | 目标制式拍板；链路预算定性分析；Python 浮点链路模型跑通 BER 曲线 | 系统规格书 v1.0 + 仿真脚本可复现 |
| **Phase 1：调制解调核心**（约 3–4 周） | 定点化；QPSK/O-QPSK 调制解调 RTL；脉冲成形（RRC）滤波器；UART/AXI-Stream 接口 | RTL 仿真 BER 与浮点模型偏差 < 0.5 dB @BER=1e-4 |
| **Phase 2：同步与信道**（约 4–6 周） | 帧/载波/定时同步；卷积码 + Viterbi；信道损伤模型注入；testbench + 覆盖率 | 端到端 RTL 仿真在 CFO/多径下链路可用 |
| **Phase 3：集成与物理实现**（约 4–6 周） | 顶层集成、寄存器接口、综合（Yosys/DC 视环境）、时序收敛、FPGA 上板（如有板卡） | 综合后无违例、资源报告、（可选）FPGA 实测 |
| **Phase 4：扩展**（弹性） | OFDM 或 LDPC 升级；极简 MAC；低功耗策略文档化 | 视时间 |

## 6. 工程规范约定

- 仓库结构：`rtl/` `tb/` `model/`（Python）`docs/` 分层；
- RTL 规范：Verilog-2001 起步，验证环境用 SystemVerilog；命名、复位、时钟域规则先写在文档里再动手；
- 所有算法先有 Python 黄金模型，再写 RTL，仿真结果必须能与黄金模型比对；
- 文档与 RTL 同步演进，每阶段出口更新一次。

## 7. 明确的"不做"清单（防止范围蔓延）

- 不做晶体管级射频电路设计与电磁仿真（天线、匹配网络、PA/LNA）；
- 不做完整的 802.11/5G NR 级协议栈与 OFDMA 多用户调度；
- 不追求 tape-out 级流程（无 PDK 环境时以综合+FPGA 为上界）；
- 不为"全面"而做：每个阶段只保留支撑出口标准的最小集。

## 8. 协作点说明（需要外部输入时）

- 射频侧协作：请提供目标频段、EVM/相位噪声预算、ADC/DAC 位数与采样率建议；
- 天线协作：提供等效增益/方向图或 S 参数文件即可；
- 若协作输入暂缺，先用业界典型值假设并在文档中标注「假设值，待确认」。
