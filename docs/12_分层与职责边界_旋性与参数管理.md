# 分层与职责边界：旋性 vs 参数管理

> 2026-09-29 一轮架构收敛的记录。核心结论：**Zigbee 单元只需要"消旋"；
> 旋性的发现、记忆、匹配、管理都可以放到上层，或转发出去做。**

---

## 0. 一句话

物理层的输出是"**给定旋性 → 干净的码片流**"。**旋性从哪来、是不是上次那台设备、
要不要记住它，都不是物理层的事。** 承认这一点之后，原本压在 RTL 上的一堆东西
（FFT、模式表、跨帧累积、淘汰策略）都可以搬走。

---

## 1. 分层

| 层 | 职责 | 本项目现状 |
|---|---|---|
| **Zigbee 单元**<br>(数字基带 / RTL) | **消旋**、匹配滤波、同步、解扩、解帧 | `rtl/rx/*`（`cfo_rot.sv` 就是消旋器） |
| **节点固件 / 主机**<br>(上层) | 旋性的**发现**(FFT)、**模式表**、记忆、匹配、淘汰 | `model/upper/patterns.py`（参考实现） |
| **网络层** | 提供"拓扑稳定 ⇒ 模式有限、切换不频繁"这一**假设** | 非本项目范围 |

**关于"模式"的一处语义澄清**（用户提出，重要）：
**模式是"物理参数的分辨单元"，不是"设备"。** 一个模式可以容纳一群设备
（只要它们的旋性落在同一分辨单元内），"坏设备"另由额外的模式容忍。
因此 **设备容量 ≠ 模式数** —— 模式数由旋性分布的分辨率决定。
推论：**淘汰策略不必严格**（一个模式服务一群设备，不会因为某台设备离开而失效）。

---

## 2. 为什么 FFT 可以"转发出去做"

| | 在单元内做 | 转发到上层/主机做 |
|---|---|---|
| 面积 | 串行 FFT + 2 KB RAM + 控制 | **只需一个前导缓冲**（256 码片 × 2 × 21 bit ≈ 10.5 kbit）+ 接口 |
| 频次 | 冷启动一次 | 同 |
| 灵活性 | 固定 | 可换算法、可跨帧累积、可与 MAC 绑定 |

**接口形状**：

```
单元 → 上层:  前导期的码片软值序列（去交错后 256 项）+ 帧到达标记
上层 → 单元:  旋性（phase_inc：每采样相位增量）
```

上层拿到 256 个码片值之后：`z[m] = v[m]·conj(c_ref[m])` → 256 点 FFT →
峰位即旋性（bin = 7.8 kHz，无模糊 ±1 MHz，实测单帧误差 ≤ 半个 bin、抖动 0）。
**这些计算对节点固件是轻量的，对 RTL 却是实打实的面积。**

## 3. 链路级实测（`run_pattern_link.py`，SNR 18 dB，40 帧/场景）

| 场景 | CFO 估计误差中位 | PER | match/discover | ms/帧 |
|---|---|---|---|---|
| 单设备 · `two_stage`（每帧盲估） | 0.0 kHz | 0.0% | — | **225.3** |
| 单设备 · `pattern`（查模式库） | 3.1 kHz | 0.0% | 39/1 | **7.7** |
| 3 设备交替 · `two_stage` | 0.0 kHz | **32.5%** | — | **234.2** |
| 3 设备交替 · `pattern` | 1.6 kHz | **0.0%** | 37/3 | **8.2** |

三点解读：

1. **速度 29 倍**：盲估每帧要做 `estimate_cfo_coarse`（±300 kHz / 10 kHz 网格
   = **61 次 IFFT/帧**）；查表命中只需一次 256 点归一化相关。
2. **多设备下 `two_stage` 的 32.5% PER**：设备旋性集合里有 350 kHz，而粗搜窗只有
   ±300 kHz ⇒ **1/3 的设备落在窗外** ⇒ 正好 32.5%。模式库的 FFT 无模糊范围 ±1 MHz
   直接覆盖。**这是"上层工具比下层网格粗搜更强"的实证。**
3. **精度的取舍**：`two_stage` 误差 0.0 kHz（因为设备频率恰好落在 10 kHz 网格上），
   `pattern` 误差 1.6–3.1 kHz（FFT bin 7.8 kHz 的量化）。**步进网格的"零误差"是对齐
   巧合，不是鲁棒优势** —— 该函数的 docstring 自己记录了"真值不落网格时会错估"。

## 4. 对 RTL 的影响

**只要守住"消旋"这一件事，RTL 侧几乎不需要为旋性的来源改动**：

- `cfo_rot.sv`：逐采样复旋转，输入 `phase_inc` + 相位重载 —— **已就位**
- 需要补的：**前导码片缓冲 + 一个上层可读的接口**（DMA / 寄存器窗口）
- **不需要**：FFT 硬件、模式表、跨帧累积器、淘汰逻辑

这同时解答了此前几轮的一个纠结："冷启动要 15 帧碰运气"是**盲估路径**的代价；
如果旋性由上层（用 FFT）一次性给出，这一项成本就消失了。

---

## 5. 遗留与开放

- **匹配分数的绝对标定**：`PatternLibrary` 的归一化相关只有 0.50–0.66（模式区分度够，
  误配 0%，但作为绝对置信度还缺乏标定）。见 I-7。
- **"转发"的物理形态未定**：缓冲多大、何时触发上传、上行带宽/时延预算 —— 取决于
  节点固件与主机的实际接口，本项目不做实现。
- **`patterns.py` 的定位**：它是**上层的参考实现**（放在 `model/upper/`），不是要硬化
  进节点的东西；淘汰策略、容量规划、模式↔设备绑定规则都留给上层真实实现。
- **盲估路径仍有价值**：若单元需要独立工作（无上层可转发），仍可用
  `two_stage`/`preamble_diff`，只是要接受其范围与鲁棒性限制。
