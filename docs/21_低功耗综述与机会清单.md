# 21 低功耗综述：方法学 · 本设计机会清单 · 三个具体问题

> 2026-10-02。面向"没做过低功耗设计"的入门总览 + 针对本设计的可执行机会清单。
> 免责：本环境无功耗工具（DC / PrimePower 级），一切以**结构性代理指标**（cells、
> 活动拍数、占空比、位宽）为口径——先做"方向正确性"，功耗签核留待有工具时。

## 1. 方法学（三条杠杆，按影响力排序）

动态功耗 **P ≈ α·C·V²·f**（α = 活动因子，C = 电容，V = 电压，f = 频率）；
静态功耗 = 漏电（与工艺/电压/温度相关）。

- **f（频率/门控）**：时钟树是动态功耗大户——**时钟门控（ICG）**是最标准的省电手段；
  次之是**数据门控/操作数隔离**（输入不翻转 → 组合逻辑不翻转 → 省动态功耗）。
- **V²（电压）**：降压最猛，但需要全局面（多电压域/低功耗流程）——**数字基带常与
  整 SoC 同域**，本设计层面可影响的有限。
- **α·C（活动/电容）**：**位宽↓、运算复用、架构简化、事件驱动**——**RTL 设计者
  的主战场**（也是本设计能直接做的）。

**"惰性（lazy）"的本质 = 让不该翻转的地方不翻转**。层次从高到低：
① 系统级（占空比/睡眠）→ ② 架构级（事件驱动、按需启用）→ ③ RTL 级（enable 门控、
运算符隔离）→ ④ 门级（综合自动，但写法要对它友好）。

## 3. 机会清单（按"收益/风险"排序）

**A. 门控与惰性化（RTL 级，立刻可做）**
1. **侦听期只留 `preamble_detect`**（最省形态：能量检测压阈值——天然适合做"唤醒检测器"）。
   **pbuf 的门控语义（2026-10-02 修正）**：唯一硬约束是"**窗内不能有洞**"（不能选择性
   跳采样），但**它可以随链路一起开关**——**睡眠期整链（ADC/MF/pbuf）全关，"历史"在
   睡眠期本不存在**；唤醒后它开始维护，价值高峰在**唤醒后的 1–5 帧**（快速启动/发现），
   **稳态接收期可关**（或仅在调试/排查模式开）。——即"必须常开"只对**醒着的链路**成立。
   **A16 扫描器**（常开）→ 检查其相关器是否"每拍全算"（可 DEC/分段惰性化）；
   **A/B 双通道的 `cfo_rot`/后端**：帧间/非帧期应停（查使能）。
2. **操作数隔离**：`cfo_rot` 复乘、`despreader` 相关树、BFP 量化器——输入未变时
   冻结输出（RTL 已多用 `if (en)` 写法，利于 ICG 推断；再审计一遍大组合块）。
3. **帧内窗口收窄**：`sfd_detect`/`despreader` 只在前导+数据窗开（已部分由
   `frame_start` 驱动——查是否真正门控）。

**A'. 门控静态审计（2026-10-02 实测，逐模块实读 RTL）**

| 模块 | 门控现状 | 判定 |
|---|---|---|
| `cfo_rot` | `if (dv_in)` 复乘/累加 | ✅ 非数据拍仅 1bit 翻转 |
| `preamble_detect` | `dv_in && sample_en`（DEC=8） | ✅ 每 8 拍一次（已最省） |
| `preamble_buf` | 每拍写 | 设计必需（窗内无洞） |
| `preamble_sync`(Csq) | 扫描器帧间仍运行 | ⚠️ **侦听期最大常开项**（已 Csq −23%；开关实验见 notes §43） |
| `deinterleave` | `if (dv_in)`（帧外照产 chip_dv） | ⚠️ 帧外仍翻转 |
| `sfd_detect` | `else if (chip_dv)`（drain 仅计数） | ⚠️ 帧外仍算 64 抽头滑窗 |
| `despreader` | `frame_start` / `chip_dv` | ⚠️ 帧外仍算 16 路相关 |
| `rx_matched_filter` | 移位线逐拍 | 随链路停（睡眠期 OK） |

**核心结论**：门控习惯整体良好（`dv`/`chip_dv` 普遍门控主 datapath）；**真缺口 =
"帧外时段"**——`busy`/窗口旗标**已存在**（§35 观测口）但**未用于门控内部运算**。
把 busy/窗旗标接到 deinterleave / sfd_detect / despreader 的运算使能，即得
"帧外零翻转"（**行为不变**——帧外本无有效数据；回归可验，活动拍统计可量化）。

**B. 位宽与架构（低风险，已有数据）**
1. **W=16 → W=14**：notes §8 实测**功能无损**（位宽砍 1/3 验证过——14~21 无损）——
   乘法器面积 ∝ 位宽²、翻转功耗 ∝ 位宽 → 数字侧直接省；
2. ~~**A16 → Csq**（I-18）~~ **已完成（v1.2 转正）**：−23% cells，且 Csq"能量定相+滑窗"的运算密度更低；
3. **±1 合流**（notes §35 ③）：sfd_detect+despreader 共享相关引擎，省 ~1k cells；
4. **单通道模式**：只用 A 时门控 B 通道（双份后端 = 双份功耗）。

**C. 采样率与 ADC（需 ref 实验 + RF 协作）**
见 §4——**这是"最大单点杠杆"**（主时钟减半 → 全链 f 减半）。

**D. 系统占空比（超出本设计范围但要知道）**
节点级的睡眠/唤醒（占空比 <1%）由固件/协议层管理；数字基带可贡献的是
**"快速唤醒同步"**（我们扫描 16 相位需数帧收敛——唤醒后同步时延是节点能耗曲线的一部分）。

### 附：pbuf 的定位修订——"快速启动资产"（用户主张，2026-10-02）

pbuf 的第一使命应是**帮助"快速启动/发现"**：唤醒后（1–5 帧内）用触发窗直接做发现与
参数估计（替代"接收机跑数十帧才收敛"）。数据背景：docs/18 记录的"前 4 帧启动瞬态"
（冷启动曾需 4 帧入稳态）——"窗内一帧定参"正是缩短该段的手段。调试回放/异常帧排查
为其副业。**低功耗形态**：唤醒链 = "pd 常开侦听（最省）→ 能量到唤醒全链 → pbuf
从唤醒起维护窗 → 触发分析"。

## 4. 三个具体问题

**① "哪里的运算可以更惰性？"**
优先级：**（a）全流常开 → 事件驱动**（pbuf/sync/cfo_rot 的使能审计）；
**（b）大组合块的操作数隔离**（复乘/相关树/量化器）；**（c）窗收窄**（sfd/despread）。
方法：统计**每模块"有效拍/总拍"**（结构性活动指标，不需要功耗工具——tb 事件流 + 计数器即可）。

**② "ADC 可以降采样率吗？"**
- **理论**：链路的采样率由"码片率 2 Mchip/s × 8 采样/码片 = 16 Msps"决定。
  **降到 4 采样/码片（8 Msps）**：半正弦成形的主能量仍可采样（需评估混叠与 MF 失真）；
  **每码片 2 采样**是理论底（Nyquist 边缘，半正弦脉冲频谱 > 1 MHz 即不够）。
- **收益形态**：**主时钟 16 → 8 MHz**（或 16 MHz 下"每两拍一采样"）→ **数字动态功耗
  近似线性减半**（同样架构下 f 减半）。
- **代价**：MF 抽头减半（38→19），定时分辨率 1/8→1/4 码片（±4 采样容差的含义变化）、
  检测/同步的统计样本减半（低 SNR 裕量下降）。
- **建议**：**先做 ref 实验**（模型侧跑"4 采样/码片"全链 BER/同步率 vs 8 采样）——
  这是"低功耗"里**性价比最高的待验证项**，而且纯模型侧、一两个小时能有结论。

**③ "12bit ADC 只量化 8bit 能提速吗？Zigbee 不需要吧？"**
- **能提速——但要点在转换器内部**：**SAR ADC 每次转换 = N 个比较周期**（N=位数）——
  **12bit→8bit 少 33% 周期** → 同工艺下**可以更快**（或同采样率下**更省功率/面积**）。
  对**我们的采样率**（16 Msps）而言，"提速"不直接变现，**省的是 ADC 功耗与模拟复杂度**。
- **"Zigbee 不需要这么高位数"——方向对，但注意两点**：
  1. **解调本身确实不需要**：模型侧 `run_quant` 已验 **4bit 也能解**（余量 ≈19 dB）；
  2. **12bit 的真实理由 = 共存/阻塞场景的动态范围**（弱信号 + 强邻道干扰同时存在时，
     量化噪声底决定灵敏度）——这是 **RF 协作边界**（`docs/06`："规格书假设 4bit，
     待 RF 协作确认"）。**结论**：把"降低 ADC 位数"作为**与 RF 联合的议价项**，
     不做单方面定案；数字侧对应杠杆（W=14/采样率）倒是可以先行。
- 附注：**"ADC 位数"与"数字内部位宽（W=16）"是两回事**——前者动模拟功耗，
  后者动数字功耗，两条线独立优化。

## 7. 门控层级：clock gating vs power gating

| | **clock gating**（时钟门控） | **power gating**（电源门控） |
|---|---|---|
| 作用 | 停局部时钟 → 寄存器/组合不翻转（省**动态**功耗） | 断局部电源（省**动态 + 静态漏电**） |
| 状态 | **保持** | **丢失**（需隔离单元 / 保持寄存器 / 上电复位） |
| 代价 | 极低（ICG 单元；综合可自动推断） | 高（隔离/开关阵列/UPF 流程/唤醒时延） |
| 粒度 | 细（模块/子模块） | 粗（电源域） |
| 本设计 | **立即可用**：帧外/侦听期门控（§3A' 缺口清单）；RTL 用 `if(en)` 写法助推断 | **属 SoC 级**：本设计先预留"休眠接口/状态保持约定"，整域断电由上层集成决定 |

**分工修正（用户观点，2026-10-03，采纳）**：**power gating 的主战场 = 模拟/RF**（睡眠期
整块断电——它们的偏置/静态电流是大头，且天生有 power-down 脚，"睡"起来干净）；
**数字端以 clock gating 为主**（帧外/侦听期门控），**不太倾向做电源门控**——数字漏电占比
低，而断电源要付"状态丢失 + 唤醒重配置"的代价。**例外**：大存储（pbuf 等）在"睡眠期
无 data-retention 需求"时可由 SoC 一并断电（内容反正要重建）。
顺序：**数字 clock gating（本设计可做）→ 睡眠期整域 power gating（模拟/RF 主导，
SoC 决策）**。

## 8. AGC：位置澄清与控制要点

**"AGC 的位置"的两件事（长期混淆点）**：
- **模拟 AGC（真 AGC）**：**ADC 之前**（LNA/VGA 可变增益 + 检波反馈环）——**唯一职责是
  把信号压进 ADC 动态范围**（不饱和 + 用满量程）；
- **数字"AGC"（`model/algo/agc.py`）**：**ADC 之后**，实为**幅度/门限估计器**——对
  802.15.4 非相干解扩的**判决无用**（|·| 免疫），服务于门限/虚警/SNR 估计。
- 结论：**"数字基带要不要 AGC 模块"是错位问法**——要的是估计器（已有：pd/estSNR/agc.py），
  防饱和归**模拟侧**（协作）。

**控制要点**（检索 + 总结）：
- **快攻击 / 慢释放**：经典 AGC 攻击数 ms 级、释放远长（Wikipedia：早期设计"时间常数
  ~1/40 s——跟随衰落、拒绝调制变化"）；**突发系统（802.15.4）**= 帧到达**极快攻击**
  （前导 4 字节内收敛）+ 帧间**慢释放/冻结**（避免噪声上抬头）；
- **目标电平**：占满量程留裕量（峰值 ~3–4σ ≤ −6 dBFS 常见）——把有效位花在信号上；
- **数字辅助 AGC**（现代 SoC 主流）：检波在数字域（我们的 **pd 能量检测 / estSNR**
  天然可当检波器），经**参数通道（已打通）**反馈 RF 增益；
- **与"少 bit 采样"的关系**：**AGC 是降位数的前置条件**（信号先占满量程，降位才有意义）。

**AGC 与"小动态范围"的配套（三层动态要分开看）**：
1. **输入动态范围**（远近/阻塞）：**由 AGC 吃掉**——有 AGC 后 ADC **不必覆盖全输入动态**，
   只需覆盖"信号带内动态 + 裕量"；
2. **信号动态范围**（调制/多径起伏）：由 ADC 位数管——zigbee 低 SNR 制式，这一项需求低；
3. **绝对摆幅**（如 0.33 V 级低摆幅/低电源设计）：**功耗 ∝ 摆幅²（∝ 电源）**，低摆幅直接省，
   但受 **kT/C 噪声下限**约束（摆幅↓ → 需更大电容，收益有边际）。
→ **"AGC + 小量程/低摆幅 ADC"对 zigbee 类是成立的**（低 SNR 容忍撑得起小摆幅），
**净收益由"我们能容忍的 SNR 底线"决定**——这正是我们该给 RF 的输入：**SNR/阻塞需求表**。

## 9. ADC 自适应（"按 SNR 选择性使用 ADC"）

- **机理**：SAR 逐 bit 测试 → **转换功耗 ∝ 位数 × 采样率**（ADI MT-021）；降位/降率直接省
  （省 ADC 功耗与模拟复杂度；对固定 16 Msps 的"提速"不直接变现）；
- **修正（用户观点，2026-10-03，采纳）**：**发现目标后不必切"全精度"**——`run_quant`
  已证 4 bit 可解、8 bit 裕量充分；**12 bit 的正当理由只有两个**：① 阻塞/共存场景的
  动态范围；② 分析模式的保真（其实 pbuf 有 BFP8，8 bit 尾数也够）。**常态档可以是
  8 bit 一直用**（"发现后切 12bit"是过度设计）；
- **节能估算（粗，依实现）**：SAR 的 **DAC 电容阵列 ∝ 2^N** → **位数是"平方级"杠杆**
  （12→8 bit：DAC 切换能量 ~1/16，加比较器 O(N) 后整 ADC 约 **3–6× 降**）；
  **采样率是线性杠杆**（16→8 Msps：约 **2× 降**）。组合（12bit@16M → 8bit@8M）≈
  **约一个数量级**（粗估）。**给 RF 的三档建议**：

  | 档 | 配置 | 用途 |
  |---|---|---|
  | 静默/扫描 | 8 bit @ 8 Msps（或更低） | 侦听（只养 pd） |
  | 通信 | **8 bit @ 16 Msps** | 常态收帧（裕量充分） |
  | 分析/阻塞 | 12 bit @ 16 Msps | 共存/环境恶劣 + 保真分析 |
- **"按 SNR 选 ADC"的鸡生蛋**：SNR 估计需要 ADC 数据 → **低配先扫、高配再精**；
- **验证抓手**：`run_quant`（4 bit 可解——通信模式 8 bit 裕量充分）；`run_snr_est`（估计已验）；
- **产出定位**：ADC 是协作边界 → 本节应落成**给 RF 的"档位需求表"**（8/12 bit 两档 +
  AGC 目标电平要求）。

## 10. 唤醒帧策略（用户定，2026-10-03）

"pd 唤醒"后的**第一帧允许失败**（试探帧，直接丢弃）——用一帧的代价换取"侦听期只开
pd"的功耗收益；**不需要**为"唤醒后第一帧的锁定率"做额外保障（热启动/相位复用仍可做，
但非硬需求）。

## 11. 开关组合省电估算（2026-10-03，结构性）

> 口径：无功耗工具；用 **cells × 活动率 α = 等效满速 cells** 作数字动态功耗代理。
> α 依据：码片节拍 1/8（`chip_dv` 实测 12.3%，notes §43 / docs/22 §11.1）、
> `preamble_detect` DEC=8、sync 扫描常开、MF/pbuf 每拍、后端模块随 chip_dv 节拍。
> （无供电控制时省的是**动态**；α 是分档近似，供方向性决策用。）

**基线等效活动分解（Csq 版 13,917 cells）**：

| 模块 | cells | α | 等效满速 | 份额 |
|---|---|---|---|---|
| `preamble_sync`(Csq) | 6,456 | 1.0（扫描常开） | 6,456 | **~80%** |
| `preamble_buf` 写 | 635 | 1.0（每拍） | 635 | ~8% |
| 后端组 ×2（sfd+desp+cfo+deframer） | 5,752 | 0.125（码片节拍） | 719 | ~9%（每路 ~4.5%） |
| `preamble_detect` | 599 | 0.125（DEC=8） | 75 | ~1% |
| MF / 小件 / 顶层（粗估） | ~475 | ~0.1–1 | ~180 | ~2% |
| **合计** | 13,917 | | **~8.0k** | 100% |

**开关方案估算**（相对基线等效活动的动态省电）：

| 方案 | 条件 | clock-gating 口径（省动态） | power-gating 口径（+漏电） |
|---|---|---|---|
| A/B 关一路（整组） | 单设备部署（`CHAN_EN`） | **~4.5%** | **~20.7%**（规模计，2,876/13,917） |
| 消旋 bypass | CFO≈0 / 非相干回退可接受（SFD 需配套，§22 §9#7） | ~0.85%/路（双路 ~1.7%） | —（bypass 通常不断模块） |
| 组合（关一路 + 保留路 bypass） | 上两者 | ~5.3% | ~24%（断电口径） |
| **对照：LISTEN 全关**（sync+pbuf+后端） | 唤醒循环（正确性已验，notes §43） | **场景相关**：连续流 6.5% 空隙 → ~6%；长 gap=50k → ~78% 空隙 → **~75%** | — |

**结论**：
- **省电大头 = LISTEN 期组门控**——80% 等效活动是“常开件”（sync 一项占 ~80% 份额）；
  “关一路/消旋”是**常驻型小肉**（与占空无关），但优先级明确：
  ① LISTEN 组门控（sync/pbuf/后端）→ ② 单设备场景关一路 → ③ 消旋按需 bypass（条件最苛刻）；
  三者可叠加（ACTIVE 期单路 + LISTEN 期全关）。
- “关一路”在小占空场景几乎不缩水（常驻收益）；“消旋”需功能前提，不宜默认开。
- 局限：结构性估计、非签核；desp 按 W12 口径（751）；cfo_rot 含 LUT→case 失真（真实为 ROM）。

pd 12.5% / chipdv 12.5% / sync 99.9%）与上表 α 分档吻合；**LISTEN 允许态折算 ≈ 112
cells-equiv ≈ ACTIVE 的 1.4%（~70×）**；现状未门控的 LISTEN 环境 ≈ 7.5–8k（与 ACTIVE
同量级）——缺口即"关断决策"未生效。策略选择（窗长/事件/状态机）另议。

## 12. 无时钟树盲估方案：两项模型 + k 区间敏感性（2026-10-03 夜）

**问题**（用户提出）：无时钟树时如何盲估功耗——不要求绝对值准，但**模块排序不能翻筋斗**
（"模型估 A≫B、真实含时钟树报告 B≫A"不可接受；模块规模本身看得准）。

**方案**（`tb/rx_dual_mc/power_est.py`，可直接复跑）：

```
W_i = (cells_i − dff_i) × α_dat_i + k × dff_i × α_clk_i
```

- `α_dat`：数据活动节拍（STATS 实测，notes §44）；`α_clk`：门控状态（LISTEN 不在允许集 → 整项归零）
- **k = 每个 dff 的等效活动成本（时钟树 + 翻转）**，推荐物理区间 **[2,8]**（对应时钟树占动态
  20–40% 的典型域）；**[1,16] 极端扫描**作透明性检验
- **承诺 = 排序保真（非绝对值）**：`≫`（≥5×）级排序在 k 区间内不翻；翻转只允许出现在
  "接近平局"（≤2–3×）的模块对

**结果（k∈[1,16] 全域）**：

- **sync 一项占 75–80%**（全区间稳定）——最大项结论对"时钟树盲区"免疫 ✓；
- **唯一"≫ 级翻转"候选：`pbuf ↔ sfd`（边缘 5.8×）**——根源是 **pbuf 使用模型**
  （设计"每拍写" vs 实测无 clr"一次性"），**不是时钟树**；确定使用模型后方向即定
  （两类模型下 k∈[2,8] 均 sfd ≥ pbuf）；
- 其余翻转对全部为"接近平局"（≤2–3×）——模型不分辨、决策上不应依赖；
- **LISTEN 允许态 = 3.8% ACTIVE**（两项模型口径；修正了纯 `cells×α` 对"常开模块
  时钟开销"的低估——pd 的 dff 项主导其残值）。

**边界（如实）**：绝对值可差数倍（时钟树/工艺/PVT 未含）；cfo_rot 的 dff=4 为 LUT→case
失真口径；本表承担"排序与占比"，绝对数不承诺。
