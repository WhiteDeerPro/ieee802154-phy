# 21 低功耗综述：方法学 · 本设计机会清单 · 三个具体问题

> 2026-10-02。面向"没做过低功耗设计"的入门总览 + 针对本设计的可执行机会清单。
> 免责：本环境无功耗工具（DC / PrimePower 级），一切以**结构性代理指标**（cells、
> 活动拍数、占空比、位宽）为口径——先做"方向正确性"，功耗签核留待有工具时。

## 1. 方法学（三条杠杆，按影响力排序）

动态功耗 **P ≈ α·C·V²·f**（α = 活动因子，C = 电容，V = 电压，f = 频率）；
静态功耗 = 漏电（与工艺/电压/温度相关）。

- **f（频率/门控）**：时钟树是动态功耗大户——**时钟门控（ICG）**是最标准的省电手段；
  次之是**数据门控/操作数隔离**（输入不翻转 → 组合逻辑不翻转 → 省动态功耗）。
- **V²（电压）**：降压最猛，但需要全局面（多电压域/低功耗流程）——**数字基带常与
  整 SoC 同域**，本设计层面可影响的有限。
- **α·C（活动/电容）**：**位宽↓、运算复用、架构简化、事件驱动**——**RTL 设计者
  的主战场**（也是本设计能直接做的）。

**"惰性（lazy）"的本质 = 让不该翻转的地方不翻转**。层次从高到低：
① 系统级（占空比/睡眠）→ ② 架构级（事件驱动、按需启用）→ ③ RTL 级（enable 门控、
运算符隔离）→ ④ 门级（综合自动，但写法要对它友好）。

## 3. 机会清单（按"收益/风险"排序）

**A. 门控与惰性化（RTL 级，立刻可做）**
1. **侦听期只留 `preamble_detect`**（最省形态：能量检测压阈值——天然适合做"唤醒检测器"）。
   **pbuf 的门控语义（2026-10-02 修正）**：唯一硬约束是"**窗内不能有洞**"（不能选择性
   跳采样），但**它可以随链路一起开关**——**睡眠期整链（ADC/MF/pbuf）全关，"历史"在
   睡眠期本不存在**；唤醒后它开始维护，价值高峰在**唤醒后的 1–5 帧**（快速启动/发现），
   **稳态接收期可关**（或仅在调试/排查模式开）。——即"必须常开"只对**醒着的链路**成立。
   **A16 扫描器**（常开）→ 检查其相关器是否"每拍全算"（可 DEC/分段惰性化）；
   **A/B 双通道的 `cfo_rot`/后端**：帧间/非帧期应停（查使能）。
2. **操作数隔离**：`cfo_rot` 复乘、`despreader` 相关树、BFP 量化器——输入未变时
   冻结输出（RTL 已多用 `if (en)` 写法，利于 ICG 推断；再审计一遍大组合块）。
3. **帧内窗口收窄**：`sfd_detect`/`despreader` 只在前导+数据窗开（已部分由
   `frame_start` 驱动——查是否真正门控）。

**A'. 门控静态审计（2026-10-02 实测，逐模块实读 RTL）**

| 模块 | 门控现状 | 判定 |
|---|---|---|
| `cfo_rot` | `if (dv_in)` 复乘/累加 | ✅ 非数据拍仅 1bit 翻转 |
| `preamble_detect` | `dv_in && sample_en`（DEC=8） | ✅ 每 8 拍一次（已最省） |
| `preamble_buf` | 每拍写 | 设计必需（窗内无洞） |
| `preamble_sync`(Csq) | 扫描器帧间仍运行 | ⚠️ **侦听期最大常开项**（已 Csq −23%；开关实验见 notes §43） |
| `deinterleave` | `if (dv_in)`（帧外照产 chip_dv） | ⚠️ 帧外仍翻转 |
| `sfd_detect` | `else if (chip_dv)`（drain 仅计数） | ⚠️ 帧外仍算 64 抽头滑窗 |
| `despreader` | `frame_start` / `chip_dv` | ⚠️ 帧外仍算 16 路相关 |
| `rx_matched_filter` | 移位线逐拍 | 随链路停（睡眠期 OK） |

**核心结论**：门控习惯整体良好（`dv`/`chip_dv` 普遍门控主 datapath）；**真缺口 =
"帧外时段"**——`busy`/窗口旗标**已存在**（§35 观测口）但**未用于门控内部运算**。
把 busy/窗旗标接到 deinterleave / sfd_detect / despreader 的运算使能，即得
"帧外零翻转"（**行为不变**——帧外本无有效数据；回归可验，活动拍统计可量化）。

**B. 位宽与架构（低风险，已有数据）**
1. **W=16 → W=14**：notes §8 实测**功能无损**（位宽砍 1/3 验证过——14~21 无损）——
   乘法器面积 ∝ 位宽²、翻转功耗 ∝ 位宽 → 数字侧直接省；
2. ~~**A16 → Csq**（I-18）~~ **已完成（v1.2 转正）**：−23% cells，且 Csq"能量定相+滑窗"的运算密度更低；
3. **±1 合流**（notes §35 ③）：sfd_detect+despreader 共享相关引擎，省 ~1k cells；
4. **单通道模式**：只用 A 时门控 B 通道（双份后端 = 双份功耗）。

**C. 采样率与 ADC（需 ref 实验 + RF 协作）**
见 §4——**这是"最大单点杠杆"**（主时钟减半 → 全链 f 减半）。

**D. 系统占空比（超出本设计范围但要知道）**
节点级的睡眠/唤醒（占空比 <1%）由固件/协议层管理；数字基带可贡献的是
**"快速唤醒同步"**（我们扫描 16 相位需数帧收敛——唤醒后同步时延是节点能耗曲线的一部分）。

### 附：pbuf 的定位修订——"快速启动资产"（用户主张，2026-10-02）

pbuf 的第一使命应是**帮助"快速启动/发现"**：唤醒后（1–5 帧内）用触发窗直接做发现与
参数估计（替代"接收机跑数十帧才收敛"）。数据背景：docs/18 记录的"前 4 帧启动瞬态"
（冷启动曾需 4 帧入稳态）——"窗内一帧定参"正是缩短该段的手段。调试回放/异常帧排查
为其副业。**低功耗形态**：唤醒链 = "pd 常开侦听（最省）→ 能量到唤醒全链 → pbuf
从唤醒起维护窗 → 触发分析"。

## 4. 三个具体问题

**① "哪里的运算可以更惰性？"**
优先级：**（a）全流常开 → 事件驱动**（pbuf/sync/cfo_rot 的使能审计）；
**（b）大组合块的操作数隔离**（复乘/相关树/量化器）；**（c）窗收窄**（sfd/despread）。
方法：统计**每模块"有效拍/总拍"**（结构性活动指标，不需要功耗工具——tb 事件流 + 计数器即可）。

**② "ADC 可以降采样率吗？"**
- **理论**：链路的采样率由"码片率 2 Mchip/s × 8 采样/码片 = 16 Msps"决定。
  **降到 4 采样/码片（8 Msps）**：半正弦成形的主能量仍可采样（需评估混叠与 MF 失真）；
  **每码片 2 采样**是理论底（Nyquist 边缘，半正弦脉冲频谱 > 1 MHz 即不够）。
- **收益形态**：**主时钟 16 → 8 MHz**（或 16 MHz 下"每两拍一采样"）→ **数字动态功耗
  近似线性减半**（同样架构下 f 减半）。
- **代价**：MF 抽头减半（38→19），定时分辨率 1/8→1/4 码片（±4 采样容差的含义变化）、
  检测/同步的统计样本减半（低 SNR 裕量下降）。
- **建议**：**先做 ref 实验**（模型侧跑"4 采样/码片"全链 BER/同步率 vs 8 采样）——
  这是"低功耗"里**性价比最高的待验证项**，而且纯模型侧、一两个小时能有结论。

**③ "12bit ADC 只量化 8bit 能提速吗？Zigbee 不需要吧？"**
- **能提速——但要点在转换器内部**：**SAR ADC 每次转换 = N 个比较周期**（N=位数）——
  **12bit→8bit 少 33% 周期** → 同工艺下**可以更快**（或同采样率下**更省功率/面积**）。
  对**我们的采样率**（16 Msps）而言，"提速"不直接变现，**省的是 ADC 功耗与模拟复杂度**。
- **"Zigbee 不需要这么高位数"——方向对，但注意两点**：
  1. **解调本身确实不需要**：模型侧 `run_quant` 已验 **4bit 也能解**（余量 ≈19 dB）；
  2. **12bit 的真实理由 = 共存/阻塞场景的动态范围**（弱信号 + 强邻道干扰同时存在时，
     量化噪声底决定灵敏度）——这是 **RF 协作边界**（`docs/06`："规格书假设 4bit，
     待 RF 协作确认"）。**结论**：把"降低 ADC 位数"作为**与 RF 联合的议价项**，
     不做单方面定案；数字侧对应杠杆（W=14/采样率）倒是可以先行。
- 附注：**"ADC 位数"与"数字内部位宽（W=16）"是两回事**——前者动模拟功耗，
  后者动数字功耗，两条线独立优化。

## 7. 门控层级：clock gating vs power gating

| | **clock gating**（时钟门控） | **power gating**（电源门控） |
|---|---|---|
| 作用 | 停局部时钟 → 寄存器/组合不翻转（省**动态**功耗） | 断局部电源（省**动态 + 静态漏电**） |
| 状态 | **保持** | **丢失**（需隔离单元 / 保持寄存器 / 上电复位） |
| 代价 | 极低（ICG 单元；综合可自动推断） | 高（隔离/开关阵列/UPF 流程/唤醒时延） |
| 粒度 | 细（模块/子模块） | 粗（电源域） |
| 本设计 | **立即可用**：帧外/侦听期门控（§3A' 缺口清单）；RTL 用 `if(en)` 写法助推断 | **属 SoC 级**：本设计先预留"休眠接口/状态保持约定"，整域断电由上层集成决定 |

**分工修正（用户观点，2026-10-03，采纳）**：**power gating 的主战场 = 模拟/RF**（睡眠期
整块断电——它们的偏置/静态电流是大头，且天生有 power-down 脚，"睡"起来干净）；
**数字端以 clock gating 为主**（帧外/侦听期门控），**不太倾向做电源门控**——数字漏电占比
低，而断电源要付"状态丢失 + 唤醒重配置"的代价。**例外**：大存储（pbuf 等）在"睡眠期
无 data-retention 需求"时可由 SoC 一并断电（内容反正要重建）。
顺序：**数字 clock gating（本设计可做）→ 睡眠期整域 power gating（模拟/RF 主导，
SoC 决策）**。

## 8. AGC：位置澄清与控制要点

**"AGC 的位置"的两件事（长期混淆点）**：
- **模拟 AGC（真 AGC）**：**ADC 之前**（LNA/VGA 可变增益 + 检波反馈环）——**唯一职责是
  把信号压进 ADC 动态范围**（不饱和 + 用满量程）；
- **数字"AGC"（`model/algo/agc.py`）**：**ADC 之后**，实为**幅度/门限估计器**——对
  802.15.4 非相干解扩的**判决无用**（|·| 免疫），服务于门限/虚警/SNR 估计。
- 结论：**"数字基带要不要 AGC 模块"是错位问法**——要的是估计器（已有：pd/estSNR/agc.py），
  防饱和归**模拟侧**（协作）。

**控制要点**（检索 + 总结）：
- **快攻击 / 慢释放**：经典 AGC 攻击数 ms 级、释放远长（Wikipedia：早期设计"时间常数
  ~1/40 s——跟随衰落、拒绝调制变化"）；**突发系统（802.15.4）**= 帧到达**极快攻击**
  （前导 4 字节内收敛）+ 帧间**慢释放/冻结**（避免噪声上抬头）；
- **目标电平**：占满量程留裕量（峰值 ~3–4σ ≤ −6 dBFS 常见）——把有效位花在信号上；
- **数字辅助 AGC**（现代 SoC 主流）：检波在数字域（我们的 **pd 能量检测 / estSNR**
  天然可当检波器），经**参数通道（已打通）**反馈 RF 增益；
- **与"少 bit 采样"的关系**：**AGC 是降位数的前置条件**（信号先占满量程，降位才有意义）。

**AGC 与"小动态范围"的配套（三层动态要分开看）**：
1. **输入动态范围**（远近/阻塞）：**由 AGC 吃掉**——有 AGC 后 ADC **不必覆盖全输入动态**，
   只需覆盖"信号带内动态 + 裕量"；
2. **信号动态范围**（调制/多径起伏）：由 ADC 位数管——zigbee 低 SNR 制式，这一项需求低；
3. **绝对摆幅**（如 0.33 V 级低摆幅/低电源设计）：**功耗 ∝ 摆幅²（∝ 电源）**，低摆幅直接省，
   但受 **kT/C 噪声下限**约束（摆幅↓ → 需更大电容，收益有边际）。
→ **"AGC + 小量程/低摆幅 ADC"对 zigbee 类是成立的**（低 SNR 容忍撑得起小摆幅），
**净收益由"我们能容忍的 SNR 底线"决定**——这正是我们该给 RF 的输入：**SNR/阻塞需求表**。

## 9. ADC 自适应（"按 SNR 选择性使用 ADC"）

- **机理**：SAR 逐 bit 测试 → **转换功耗 ∝ 位数 × 采样率**（ADI MT-021）；降位/降率直接省
  （省 ADC 功耗与模拟复杂度；对固定 16 Msps 的"提速"不直接变现）；
- **修正（用户观点，2026-10-03，采纳）**：**发现目标后不必切"全精度"**——`run_quant`
  已证 4 bit 可解、8 bit 裕量充分；**12 bit 的正当理由只有两个**：① 阻塞/共存场景的
  动态范围；② 分析模式的保真（其实 pbuf 有 BFP8，8 bit 尾数也够）。**常态档可以是
  8 bit 一直用**（"发现后切 12bit"是过度设计）；
- **节能估算（粗，依实现）**：SAR 的 **DAC 电容阵列 ∝ 2^N** → **位数是"平方级"杠杆**
  （12→8 bit：DAC 切换能量 ~1/16，加比较器 O(N) 后整 ADC 约 **3–6× 降**）；
  **采样率是线性杠杆**（16→8 Msps：约 **2× 降**）。组合（12bit@16M → 8bit@8M）≈
  **约一个数量级**（粗估）。**给 RF 的三档建议**：

  | 档 | 配置 | 用途 |
  |---|---|---|
  | 静默/扫描 | 8 bit @ 8 Msps（或更低） | 侦听（只养 pd） |
  | 通信 | **8 bit @ 16 Msps** | 常态收帧（裕量充分） |
  | 分析/阻塞 | 12 bit @ 16 Msps | 共存/环境恶劣 + 保真分析 |
- **"按 SNR 选 ADC"的鸡生蛋**：SNR 估计需要 ADC 数据 → **低配先扫、高配再精**；
- **验证抓手**：`run_quant`（4 bit 可解——通信模式 8 bit 裕量充分）；`run_snr_est`（估计已验）；
- **产出定位**：ADC 是协作边界 → 本节应落成**给 RF 的"档位需求表"**（8/12 bit 两档 +
  AGC 目标电平要求）。

**RTL 实测（2026-10-03 夜，"ADC 量化调节"起手）**：用 `gen_quant_scenes.py` 把 snr20/snr6 的
mem 按 N-bit 再量化（同满量程，LSB=2^(12-N)），RTL 真链跑 FRMA：

| ADC 位宽（round） | snr20 | snr6 |
|---|---|---|
| 12（基准） | 60/60 | 15/60 |
| 8 | 60/60 | 15/60 |
| 6 | 60/60 | 15/60 |
| 5 | 60/60 | 16/60 |
| 4 | 60/60 | 16/60 |
| 3 | **60/60** | — |
| 2 | 23/60 | — |
| 4（floor 截断） | **19/60** | — |

**三条结论**：
1. **数字链鲁棒性远超预期**——工作点下 **3 bit 即可全收**（2 bit 才断），"通信 8 bit"
   裕量达 5 bit，**数字侧不构成档位约束**；
2. **量化"无偏性"比位宽更关键**——同 4 bit：舍入 **60/60** vs 截断 **19/60**（floor 的
   系统偏置是相干损伤）——**给 RF 的档位约定必须写明"无偏/舍入量化"**；
3. 低 SNR（snr6）下位宽不是瓶颈（≈15–16/60 与 12 bit 持平，噪声主导）。

→ 档位取舍**可大胆让位于模拟侧节能与动态范围**；极端静默档可探索 3–4 bit。
（复现：`gen_quant_scenes.py` → `simv_stats +CKS=<meta.mem_cks>` → FRMA 口径。）

**开关方案估算**（相对基线等效活动的动态省电）：

| 方案 | 条件 | clock-gating 口径（省动态） | power-gating 口径（+漏电） |

- **省电大头 = LISTEN 期组门控**——80% 等效活动是“常开件”（sync 一项占 ~80% 份额）；

- “关一路”在小占空场景几乎不缩水（常驻收益）；“消旋”需功能前提，不宜默认开。

## 12. 无时钟树盲估方案：两项模型 + k 区间敏感性（2026-10-03 夜）

**问题**（用户提出）：无时钟树时如何盲估功耗——不要求绝对值准，但**模块排序不能翻筋斗**
（"模型估 A≫B、真实含时钟树报告 B≫A"不可接受；模块规模本身看得准）。

**方案**（`tb/rx_dual_mc/power_est.py`，可直接复跑）：

```
W_i = (cells_i − dff_i) × α_dat_i + k × dff_i × α_clk_i
```

- `α_dat`：数据活动节拍（STATS 实测，notes §44）；`α_clk`：门控状态（LISTEN 不在允许集 → 整项归零）
- **k = 每个 dff 的等效活动成本（时钟树 + 翻转）**，推荐物理区间 **[2,8]**（对应时钟树占动态
  20–40% 的典型域）；**[1,16] 极端扫描**作透明性检验
- **承诺（v2 修订，按用户裁决）**：红线 = 禁止"**大反转**"（两方向均 ≥5× 的对手出现）；
  **近似模块允许"排不出顺序"**（排名带重叠即不给定序）；绝对数值不承诺

**结果（k∈[1,16] 全整数扫描；v2 工具输出）**：

- **红线检查（大反转 = 两方向均 ≥5×）：零违规 ✓**。唯一"单侧 ≥5× 且曾跨方向"的对手 =
  `pbuf ↔ sfd`（顺向 5.85×@k=16 / 反向仅 1.06×@k=1——反向属平局级摆动，**非大反转**；
  **推荐区间 [2,8] 内方向稳定为 sfd ≥ pbuf，1.3–3.5×**）；
- **排名带**（[2,8] / [1,16]）：sync 1..1；sfd 2..2（→2..3）；pd 3..4；pbuf 3..5；
  desp 4..5；胶合 6..6；cfo·deframer 7..8；pn9 9..9；MF 10..10；deint 11..11——
  **带重叠处 = "排不出顺序"，不给定序**；
- **可承诺强关系**（任意 k 恒 ≥3×）：sync ≫ 全部（最低 9.2×）；sfd > {MF,deint,cfo,
  deframer,pn9,胶合}；pd > {MF,deint,deframer,pn9}；pbuf > {MF,deint}；desp > {MF,deint,
  deframer,pn9}；胶合 > {MF,deint}；…（完整清单 = 脚本输出）；
- 占比区间（k∈2..8）：sync 76.9–79.1%、sfd 7.5–8.4%、pbuf 2.4–5.6%、pd 2.9–3.9%、
  desp 2.5–2.8%、…；
- **LISTEN 允许态 = 3.8% ACTIVE**（两项模型口径；修正纯 `cells×α` 对"常开模块
  时钟开销"的低估——pd 的 dff 项主导其残值）。

**边界（如实）**：绝对值可差数倍（时钟树/工艺/PVT 未含）；cfo_rot 的 dff=4 为 LUT→case
失真口径；本表承担"排序与占比"，绝对数不承诺。

## 13. 单位时间功耗对照（平均功率；2026-10-03 夜）

> 口径（按用户裁决）：以**单位时间功耗（平均功率）**为主——能量累计随等待时长线性
> 放大、公平性差，改以功率做数。P_avg = (W_act×T_act + W_lst×T_gap)/T_total（时间加权）；
> 基准 = **ACTIVE 每拍功率 = 1.00**（k=4 主口径；k∈[2,8] 见脚本）。

**每拍功率：ACTIVE : LISTEN = 26×（23–30×）**

| 场景 | 门控后 P_avg（相对 ACTIVE） | 未门控 P_avg（现状） |
|---|---|---|
| snr20（连续帧） | **97.8%** | 100% |
| listen1（gap=50k） | **26.1%** | 100% |
| Zigbee 100 帧/s | **12.9%** | 100% |
| Zigbee 1 帧/s | **3.9%** [3.4–4.4%] | 100% |

**读法**：

- 现状（未门控）**任何帧率下平均功耗≈顶格**（100%）——"等多久都付一样的钱"；
- 门控后平均功耗随帧率下降（稀疏场景 1 帧/s 只付 **3.9%**）——**LISTEN 全关把"等待"
  从按时间计费改为按 1/26 计费**；
- 收帧时段的功率（ACTIVE）不变——省电全部来自"等待期重定价"。（能量=功率×时长；
  累计能量口径已改为此功率口径。）

## 14. ADC 自适应：鸡生蛋的解与单调场景验证（调研 + 仿真；2026-10-03 夜）

### 14.1 调研要点（外部资料）

- SAR ADC 功耗随**分辨率与采样率**近似线性/显著增长（TI slyt605；Wikipedia）——降位/降率是直接杠杆；
- **自适应分辨率接收机已有先例**：Zhu et al.（A-SSCC 2013）——"全 ENOB 不必要时省电"；
- **常开侦听的低精度实践**（WuRx）：包络检测 / 4-bit flash ADC 即可支撑唤醒检测
  （Pletcher JSSC'09 52µW；Huang ISCAS'13 4-bit）——"relaxed sensitivity allows lower-resolution
  ADC"（Magno et al., Sensors'19 综述）；
- 权衡需**联合选择**：分辨率 × 占空比 × 前端增益 × 前导长度（同上综述）。
- 与本设计对照：我们的"能量法定档"（`run_snr_est` 三档可分、慢变跨帧）≈ WuRx"粗检测先导"
  的数字化版本。

### 14.2 鸡生蛋的解：不对称原则（设计；按用户"分权"修正 2026-10-03）

问题："按 SNR 选 ADC"需要 SNR 估计，而估计需要 ADC 数据。解——**进入/离开不对称 + 权级分层**：

1. **进入（降档）：自动**——仅由高精度状态发起（先看清、有裕量证据才降；禁止低档
   链式自降）；常态自动，**不搞额外仪式**；
2. **离开（升档）双通道**：
   - **自动**：失败类信号（FCS/同步失败在低精度下依然可信）或 TTL 兜底到期回顶；
   - **force**：外部强制（电平，帧边界采样）——**覆盖基带的自动判断**：即便基带自行
     评估认为"可以不恢复"，外部也能强制其进入全态（12bit）并清计数；
3. **权级**：基带自动逻辑 < 外部 `force`（最高权限；用于"此刻必须全保真"的场景——
   重要流量 / 调试 / 共存恶劣期）。

→ 保证"**不会困在低精度**"：自动通道有失败触发 + TTL 兜底；**force 提供无条件出口**。

### 14.3 单调场景仿真（`model/experiments/run_adc_gear.py`）

场景：1800 帧 = 20dB 保持 300 + 单调下降（−2dB/100 帧）至 2dB + 保持 300 + 回升至 20dB 200 帧；
模型 = 量化噪声合成（SQNR=6.02N+1.76）+ 实测锚点校准（示意级，非实测）。结果（20 seeds）：

| 策略 | 平均功耗 | /fix12 | 高段失败（环境≥14dB） |
|---|---|---|---|
| fix12（基线） | 2.000 | 1.000 | 20.9 |
| **gear 默认**（th8=18/th4=20） | **1.719** | **0.859** | 24.4 |
| gear 保守（20/22） | 1.751 | 0.875 | **20.2** |
| gear 激进（16/18） | 1.604 | 0.802 | 25.9 |
| oracle（先知最优） | 1.646 | 0.823 | 26.6 |

- **gear 默认达先知最优的 104.4% 功耗**（1.719 vs 1.646），相对 fix12 省 **14.1%**；
- **降档成本小**：高段失败 +3.5 帧/1800（0.2%），与 oracle 同级（同源于"0.95 裕量阈值"）；
- 轨迹（每 100 帧采样）：`4 4 4 4 4 4 8 8 12 12 12 12 12 12 12 12 8 8`——
  高档起步→高 SNR 降档→环境恶化升档→**回升后重新降档**；**全程无死锁**；
- 阈值敏感性清晰（保守↔激进：失败 20.2↔25.9，功耗 0.875↔0.802）——按需选点；
- 语义注明：TTL 复查 = **无条件回顶**（低档不能自评——与 §14.4 RTL 同一语义）。

## 15. 证据-决策解耦与权限模型（规划 + 量化动态化接口 v0；2026-10-03 夜）

### 15.1 问题与动机（用户提出）

- **证据（评估/量化）与决策是两块工程**：
  ① 评估动作本身有成本 → 要**"更少地量化"**（稀疏、按需、窗口化）；
  ② 降量化不是一味好 → **需要有依据地调节**（结论必须从证据来）；
- 因此分层：**量化工程**（接口/证据收集/执行）⇄ **决策工程**（状态机/权限）。

### 15.2 业界锚点（调研）

- **Intel HWP/EPP（Speed Shift）**：处理器**硬件自治选档**（快）+ OS/驱动经 **EPP 给偏好**、
  设 **min/max 允许边界**、按策略 govern/override——"**自治 + 偏好 + 边界 + 覆盖**"。
  同构映射：基带自动 ⇄ 硬件自治；**permit ⇄ EPP 偏好**；**GEAR_MIN ⇄ min/max 边界**；
  **force_full ⇄ 覆盖**。（同族：ACPI OSPM 分层、安全监控器强制态。）

### 15.3 双层架构与权限矩阵

```
[决策工程] 证据 → 允许/强制                [量化工程/执行]
  adc_gear_ctrl（演化）:                     adc_quant_if（已造 v0）:
  · 简单 FSM，倾向高精度（约束）                · 档位寄存器 + req/ack 握手
  · 机会主义: 指标 OK → permit ───────▶    · 权限闸门（升恒允许/降需 permit/force 强制）
  · 强退: 不安全 → 无条件拉高                    · 面向 ADC/RF 的切换请求
  · 外部代理: force_full（权限委派）
```

**权限矩阵**（谁能做哪个转换）：

| 转换 | 决策层自动 | 外部代理 | 闸门规则 |
|---|---|---|---|
| →更高精度（升/强退） | ✅（失败/TTL） | ✅ force_full（无条件） | 恒允许 |
| →更低精度（降） | ✅ 仅在 permit 条件下发起 | ❌（默认无此权） | 需 set_low_ok 且 ≥GEAR_MIN |

### 15.4 量化动态化接口 v0（已制造）

- `rtl/rx/top/adc_quant_if.sv`：`set_gear/set_req/set_low_ok/set_force_full` →
  `adc_gear/adc_req/adc_ack` + `denied` 观测；`GEAR_MIN` 下限边界；忙时忽略
  （约定决策层不忙再发）；
- 测试：`tb/adc_quant_if`（cocotb）——权限矩阵 6 项断言全过（无 permit 拒 / permit 过 /
  升恒允许 / force 强制+拒降 / 释放恢复 / 忙保护）。

### 15.5 "更少地量化"与评估调度（设计原则）

- 评估（高精度窗口 + 估计）应为**稀疏事件**（TTL/失败/外部触发）——频率旋钮 =
  证据成本 ↔ 决策质量；
- "不是越少越好"：降档依赖证据充分性；约束侧的保守倾向（默认高精度）提供兜底正确性。

### 15.7 振荡边界实验（"降档不常见"的验证/反驳；2026-10-03 夜）

问题（用户裁定 b 方案时提出）: 估计器会不会在阈值附近**振荡**使 permit 频繁翻转？
方法: 落实估计器 ref（`model/algo/snr_est.py`——能量法, q20 噪声窗, 对应 RTL pwr/nse）
+ 围绕降档阈值生成 14–21dB 流（各 40 帧）→ 逐帧估计 → 阈值扫描的翻转率。

**结果**：(工｜`model/experiments/run_gear_chatter.py`)

- **估计口径**: 帧间 **σ_est ≈ 0.28–0.30 dB**（q20 窗，小）；相对环境标签有 ~5.5dB
  系统偏移（口径常数，阈值须按估计口径标定）；
- **阈值对准均值时：真振荡**——最坏翻转率 **0.61–0.66/帧**（≈1.5 帧一翻）；
  但翻转带**窄**：≥50% 峰值带宽仅 **0.45–0.65 dB**（≈±1σ）；
- **2dB 滞回（现设计 18/16 间距）完全消抖**：全环境点 **0.000/帧**；
- **慢漂移穿越**（19→17dB/60 帧）：无滞回 **17 次**翻转；滞回后 **1 次**（干净单穿越）；
- **振荡带换档伤害实测**：17/19dB 下 q4 vs q12 均 **40/40**——两档等价区，
  **即使振荡发生时换档也无性能损失**（只余切换能耗）。

**结论**："降档不常见"**在"有滞回"前提下成立**（无滞回则不成立——阈值附近/慢穿越
确会 chatter）；现设计的 2dB 滞回已覆盖（成本零）；b 方案（permit 仅输出标）下消费侧
还可再加节流作双保险。**伤害上界 = 切换能耗**（性能无损）。

## 16. 控制论视角：门控与档位决策的分层分析（2026-10-03 夜）

> 用一般控制论语言重述两件事——① 档位决策（gear）；② 门控体系——并给"决策分层"
> 提供结构根据（时间尺度/带宽分离 + 监督控制）。全部结论均有本仓实验数据支撑。

### 16.1 档位调节 = 带观测器与滞回的继电反馈环（relay + hysteresis）

| 控制论元件 | 本系统 |
|---|---|
| 被控对象（plant） | 信道 + ADC + 数字链（带宽受限） |
| 扰动 | 信道 SNR（慢漂移）+ 帧间噪声（快） |
| 观测器（observer） | 能量法 SNR 估计（q20 窗）——**测量噪声 σ_est ≈ 0.3 dB**（实测） |
| 控制器 | gear FSM = **带宽滞回的继电控制器**（relay with hysteresis） |
| 执行器（actuator） | 量化动态化接口（离散档位 + 握手 + 切换成本） |
| 设定/偏好 | 阈值组合（18/16）、`GEAR_MIN`、permit |
| 监督层（supervisor） | `force_full` / 权限矩阵（覆盖无条件） |
| 无滞回反例 | 经典 chattering——实测 **0.605 翻转/帧**（§15.7） |

**定量闭环（§15.7/16.4 数据）**：观测器噪声 0.3dB → 经典死区设计 ≈6σ≈1.8dB →
滞回扫描显示 h≥1.0–1.5dB 即消抖 → **现设计 2dB 恰好成立且有半格余量**。
**参数是"算出来"的。**

### 16.2 门控体系 = 事件触发的开关系统（event-triggered switched system）

- **LISTEN↔ACTIVE = 开关系统的模式切换**，切换律由 **pd_rise 事件触发**（而非周期
  时钟）——即 **event-triggered control** 的节能形态；触发条件质量（CFAR 虚警/漏检）
  直接决定切换可靠性；
- **冻结/唤醒 = 带状态保持或重置的切换**——**"对齐复位器" = reset control**：切换瞬间
  的状态重置必须保证**不发散**（"轴交换" = 重置映射错位；已由 关 3–513 拍全绿实验闭环）；
- **不可关的 `smp_cnt` = 时间基准/积分器**——开关系统不可切掉的轴；
- **探测帧可弃 = 切换暂态的误差预算**；
- **"门控状态循环" = 周期轨（极限环）**："较好的循环" = 稳定低代价的周期轨；v1 帧窗
  实测"恒开" = 周期轨退化（无循环）——目标是把循环修回"帧期激活/侦听空转"。

### 16.3 决策分层的结构根据：带宽分离 + 独立监督

| 层 | 控制论角色 | 时间尺度 | 件 | 准则 |
|---|---|---|---|---|
| L0 | 对象 | 每样品 | 链/ADC | — |
| L1 | 观测器 | 每帧（~1ms） | `snr_est`/失败统计 | 噪声 σ 定死区 |
| L2 | 控制器（滞回） | 帧~十帧 | gear FSM | 滞回 ≥6σ；禁链式=开环限幅 |
| L3 | 执行器 | 切换事件 | `adc_quant_if` | 事务边界 + 握手 |
| L4 | 监督 | 秒级/外部 | force/权限 | 安全方向恒允许；覆盖无条件 |
| L5 | 调度/策略 | 上层 | TTL/门控循环 | 内外环带宽比 5–10× |

要点：① 各层**带宽分离**（内环快于外环）是"分层不打架（无谐振）"的条件——本设计
天然满足；② **监督层的独立性**（安全不依赖下层自主判断——force 直连执行器、升档恒允许）。

### 16.5 结论

- **档位决策 = 继电控制 + 滞回 + 监督覆盖**——σ→2dB→0 翻转→伤害 0，链条完整；
- **门控 = 事件触发开关系统 + 重置控制**——"对齐复位"即其稳定性条件；
- **决策分层 = 带宽分离的多环 + 独立监督层**——不是风格选择，是控制论上"可论证
  不打架"的结构（本仓实验逐条支撑）。
