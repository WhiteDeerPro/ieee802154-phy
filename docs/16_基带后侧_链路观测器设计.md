## 1. 定位：为什么需要它

### 1.1 现状的三个缺口（都有实测依据）

| 缺口 | 实测证据 |
|---|---|
| **冷启动慢** | 自主触发要 ~15 帧才碰到一次高质量估计（`cfo_trigger/report.md` §9.5：前 14 帧 cf≤0.26 被拒，第 15 帧 cf=0.89 才捕获） |
| **收敛后仍偶发失败** | 每 ~10 帧一次坏估计 + 该帧同步失败（同上 §9.5） |
| **无跨帧记忆** | 每帧都从零开始；RTL 的门控（`EST_REQ_QUAL`）是**单帧硬判决**，不利用历史 |

三个缺口的共同根源：**接收机被当作"每帧独立"处理，而实际链路是"状态慢变"的**。

### 1.2 与既有分层的关系（`docs/12`）

```
RTL（单元）        ：消旋、MF、同步、解扩、解帧      —— 只干活
本模块（后侧/上层）：观测、状态估计、控制决策        —— 长脑子
网络层            ：提供"状态有限、切换不频繁"假设  —— 非本项目
```

`patterns.py` 提供"状态表 + 匹配/发现"（帧级、无状态）；本模块补上**跨帧状态机 + 证据累积 + 控制输出**。

## 2. 理论基础（调研）

### 2.1 多帧证据累积

- **相干积分**（复数样本求和）：SNR 增益 ∝ N；
- **非相干积分**（包络求和）：增益 ∝ √N，但容忍相位不稳。

二者是"多次弱观测换一次可靠判决"的经典形式；代价是更长的驻留时间。

### 2.2 序贯检测（SPRT, Wald）

每帧更新似然比，三选一：接受 / 拒绝 / 继续，直到越过阈值。
**平均观测数低于固定 N 的检验**——这正是"不必等一个完美单帧，累积到足够就判决"的理论形式。

### 2.3 捕获状态机与热启动（GNSS 类比）

GNSS 捕获的标准结构是 **Search → Verification → Lock/Tracking**：
检测命中后先"验证"（M/N 确认），失败退回搜索并付一次虚警代价 `K`。
平均捕获时间：

```
E[T_acq] = (2−P_d)/(2P_d) · (1 + K·P_fa) · q · τ_d
```

`q` = 搜索单元数。**冷启动扫全格（q 大）；热启动用存储的星历/位置直接砍掉 q** ——
这就是"用历史把冷启动变热启动"的数学依据。对应到本项目：

| GNSS | 本项目 |
|---|---|
| 冷启动（无星历） | 无状态表 → 盲搜（现 ~15 帧） |
| 温启动（粗略位置/时间） | 状态表有相近项 → 有限搜索 |
| 热启动（星历） | 状态命中 → 直接给 `phase_inc`（目标 ~1 帧） |

### 2.4 估计精度的极限（CRLB）

单音频率估计的精度存在 Cramér-Rao 下界，随**观测时长与 SNR** 提升；
CFO 与 SFO 联合时还有 hybrid CRLB（Springer 2022）。
推论：**单帧前导只有 128 µs，想更准必须多帧联合**——算法再好也突破不了观测长度给的下界。

### 2.5 "CFO 相干块"（多帧联合估计）

最新文献提出 **CFO-coherent block** 概念：先声明"一段时间内 CFO 恒定"，
再在块内**相干聚合多个同步块**做联合估计（arxiv 2512.01386, Joint CFO-Channel
Estimation over CFO-Coherent SS Burst Sets）。
这正是本项目"旋性/状态"概念的学术对应物——**状态 = 块内公共参数**。

## 3. 状态模型与术语

### 3.1 术语（替代"模式"）

- **链路状态（link state）**：一组会被多帧复用的物理参数
  （当前：`cfo`；可扩展：DC/定时/IQ）。
- **状态表（state table）**：已识别状态的集合（`patterns.py` 的 `PatternLibrary`）。
- **状态辨识 / 捕获（identification / acquisition）**：从观测中确定当前状态。
- **状态关联（association）**：把观测归到已有状态（雷达 data association 的用法）。
- **老化（aging）**：长期未命中则移除。

### 3.2 状态机

```
SEARCH ──证据达标──> VERIFY ──连续命中──> LOCK
   ↑                    │证据衰减            │ 连续失效
   └────────── LOST ←───┴────────────────────┘
```

- **SEARCH**：证据不足；可请求**全信息观测**（256 码片，供 FFT 发现）。
- **VERIFY**：候选证据达标，试探性输出 `cfo_hint`（低频度、低置信）。
- **LOCK**：M/N 确认后锁定；输出全信 `cfo_hint`；写回持久状态表。
- **LOST**：连续失联；保留历史（重捕获走"温启动"而非冷启动）。

## 4. 架构与接口

### 4.1 观测（每帧，便宜）

```python
FrameObservation(idx, cfo, quality, sync_ok, fcs_ok)
# cfo/quality 来自基带估计器（cfo_est 的 phase_inc 与 cf）
# 可选: raw 前导码片（SEARCH 态才需要 —— 分级观测, 见 §5.4）
```

### 4.2 控制（给基带矫正模块）

```python
Control(state, cfo_hint, want_raw, confidence)
```

### 4.3 与 RTL 的接口契约（部分已实现）

| 方向 | 承载 | 频率 | 状态 |
|---|---|---|---|
| 单元 → 后侧 | 每帧：估计值 + 质量 + 成败 | 每帧 | ✅ 现成（`phase_inc`/`cf`/`fcs_ok`） |
| 单元 → 后侧 | 前导码片软值（256×2×21 bit） | 按需（SEARCH） | ⬜ 需 I-13 缓冲 |
| **后侧 → 单元** | **`phase_inc` 预置（外部参数通道）** | **LOCK 后按需** | ✅ `rx_top.ext_inc_en/ext_inc/ext_phase_off`（2026-10-01 打通） |
| 后侧 → 单元 | 门限/模式开关 | 低频 | ⬜ 需扩接口 |

**两种落地形态（都已验证）**：

- **离线文件驱动**（`run_observer_replay.py`）：RTL dump EST 事件 → Python 处理 →
  参数文件（可标"第 N 帧生效"模拟任意延迟）—— 分析算法随便换；
- **在线 DPI**（`observer_dpi.c` + `+DPI=1`，见 §7.4）：仿真中每次 `est_done` 调用 C 侧
  观测器，LOCK 后经外部参数通道接管 —— **固件在环**的预演。

> 与既有 `--fixinc` 的区别：后者是 tb 对 `inc_reg` 的层次化强制（诊断 hack、不可综合），
> `ext_inc` 是正式端口。

## 5. 参数获取方法：可插拔的方案空间（"模式获取"）

问题：**如何从观测中确定链路状态（当前主要是 CFO）？** 分三条路线。

### 5.1 频域路线（FFT + 插值）

- 去调制后 `z = v·conj(c_ref)` → 256 点 FFT → 峰位 = CFO（本项目已实现：
  bin 7.8125 kHz、无模糊 ±1 MHz、全 CFO 20/20、抖动 0）；
- 文献结论：**单音的 ML 估计就是周期图最大化**，FFT 是它的快速网格实现
  （Rife & Boorstyn 1974），SNR 门限之上达到 CRLB；
- 目前只取整 bin（7.8 kHz 量化），**FFT 插值**（Quinn）可细化到渐近有效；
- MUSIC/ESPRIT 属超分辨方法，需要模型阶数假设——**单音场景不必**（Stoica & Nehorai 的对比结论）。

### 5.2 时域路线（相位轨迹拟合）

不碰 FFT 的做法：前导已知 → 去调制得相位序列 `φ[m]`（本项目有 `cordic_atan2`）→
**展开相位后做（加权）线性拟合**，斜率即 CFO。

- 与 FFT 的关系：对高 SNR 场景（相位可测），相位轨迹的加权最小二乘**就是**
  相位域 ML，精度同样逼近 CRLB；
- 与现状的关系：`cfo_est` 用"跨 2 码片差分 + 累加"（固定间隔），
  而线性拟合**用上所有间隔**——同样的数据、更充分的利用；
- 代价：需要相位展开（对噪声敏感，通常要求已粗消旋 → 适合 LOCK 后的精估/跟踪）。

### 5.3 递归路线（卡尔曼 / α-β 滤波）

把 `[φ, f]` 作为状态、每帧的相位/频率观测作为测量，做**递归贝叶斯更新**。

- 天然支持多帧与失联（过程噪声 + 观测缺失）；
- **协方差直接给出置信度**——`docs/08` I-7 要的"统一置信度体系"在这里有严格形式；
- 本模块的"证据累积"是其粗粒度近似；将来可把 `LinkObserver` 内部升级为状态空间滤波。

### 5.4 设计原则：方法可插拔，不预设实现

上面的三条路线**不是"选一个"，而是接口固定、实现可换**：

- 观测器只依赖 `(cfo, quality)` 这样的**标量契约**（§4.1）—— 谁产生它都行：
  FFT、相位拟合、递归滤波、查表、甚至学习类模型；
- 状态机 / 证据累积 / 控制逻辑与估计器**解耦**（`observer.py` 不 import 任何估计实现）；
- 因此"用不用频域"不是架构问题，而是**每个阶段的实现选择**：

| 阶段 | 倾向 | 理由（非强制） |
|---|---|---|
| SEARCH（冷启动） | 无先验、范围宽的方法（FFT 是现成选项） | ±1 MHz 无模糊、免相位展开 |
| VERIFY / LOCK（跟踪） | 精度高、成本低的方法（相位拟合 / 递归滤波） | 已粗消旋，相位可测 |

### 5.5 方案空间（按适用条件列，不做原则性排除）

| 方法 | 适用条件 | 本项目现状 |
|---|---|---|
| FFT / 周期图（+插值） | 无先验、范围宽 | 已实现（`run_cfo_fft`），冷启动首选 |
| 相位轨迹拟合（时域 ML） | 相位可测 | 与 `cfo_est` 同源，可作 LOCK 精估 |
| 递归滤波（卡尔曼 / α-β） | 需要连续跟踪 + 严格置信度 | 未实现；证据累积是其粗粒度近似 |
| 匹配相关（模板枚举） | 状态集合有限 | 已实现（`patterns.py` 的 `match`） |
| 子空间（MUSIC / ESPRIT） | 多音 / 超分辨 | 单音不必；若将来状态含多径特征可再看 |
| 小波 / 时频工具 | 非平稳、瞬态检测 | CFO 在相干块内平稳，**当前无优势**；属备选，非排除 |
| 数据驱动 | 有充足数据 | 备选（可作为后端增强） |

**"全信息观测"同样按需**：SEARCH 给原始码片（供任意后端分析），LOCK 只给标量 ——
观测粒度跟着状态走，而不是固定带宽。

## 6. ref 实现（`model/upper/observer.py`）

已实现 §3.2 状态机 + 质量加权证据累积（泄漏积分）+ 控制输出 + 热启动/记忆 +
**多状态并存**（每个候选自带状态机；一帧观测按分辨单元宽 `tol_hz` 归类）+
**服务调度**（RRM 风格，见 §7.2）。
核心参数：`q_floor`（质量地板）、`acquire_th`（捕获阈值，等效满分帧数）、
`decay`（每帧衰减，近期优先）、`verify_hits`（M/N 的 M）、`lost_run`、
`tol_hz`（分辨单元宽）、`serve_window`（调度服务窗口）。

**验证**（`model/tests/test_observer.py`，合成观测，**18/18 PASS**）：

- 连续好帧 → 3 帧内 LOCK；单帧高分**不会**锁定（抗虚警）；
- LOCK 后扛 2 帧失联；3 帧转 LOST；恢复后 2 帧重锁；
- `warm_start` 立即 LOCK；状态跳变最终重锁到新值；
- **多设备交替**：各状态分别 LOCK；**共享分辨单元**：3 台相近设备落进同一个锁定状态。

另有 **C 实现**（`tb/rx_chain_e2e/observer_dpi.c`，同结构，单候选简化）经 DPI-C
在仿真中实时运行（§7.4）。

## 7. 验证：真实链路回放（已执行 2026-10-01）

**数据**：`tb/rx_chain_e2e` 自主触发模式 dump 的 EST 序列
（CFO=100 kHz，50 帧 → 42 次估计；仿真复现 `cfo_trigger` §9.4 的 25/50）。
**脚本**：`model/experiments/run_observer_replay.py`（读 `events.txt`，回放观测器，出报告）。

**结果**：

| 路径 | 首次采纳/锁定 | 值 | 误差 |
|---|---|---|---|
| 现状（RTL 单帧硬判决） | 第 11 次估计（`est_ok=1`） | +178.5 kHz | **78.5 kHz（错）** |
| 观测器（多帧软判决） | 第 19 次估计（LOCK） | +99.1 kHz | **0.9 kHz** |
| 热启动 | 0 帧捕获 | +98.3 kHz | 1.7 kHz |

三点解读：

1. **单帧硬判决会采纳假象**：第 11 次 cf=0.26 刚过门限、值却是错的（178.5 kHz），
   RTL 直接采纳；观测器因证据不足拒掉（权重仅 0.0125）。
2. **锁定质量差 ~80 倍**：0.9 kHz vs 78.5 kHz；锁定后 EMA 跟踪稳定
   （hint 从 +99.9 缓慢跟到 +100.4 kHz @ 第 42 帧）。
3. **抗单帧抖动**：第 41 次坏估计（-297.8 kHz, cf=0.03）不影响 LOCK。

> 注：观测器比 RTL 晚 8 次估计进入锁定，但 RTL 那次锁定是错的 —— 这不是速度劣势，
> 而是"不犯错"的代价；`acquire_th` 可调此权衡。

**待做**：多设备 / 设备换频场景的批量回放（对齐 `docs/14` I-16）。

### 7.2 多设备场景与服务调度（已执行 2026-10-01）

模型（按与用户对齐的领域假设）：14 台设备 = 主群 8（晶振相近）+ 次群 4 + 离群 2；
帧流**按突发**交错（时间局部性）、**准静态**（不做剧烈换频）；**单消旋器**约束；
观测质量取决于当前 hint 是否覆盖该设备。脚本 `run_observer_multidev.py`（600 帧）。

**调度前**（纯匹配驱动）：主群好帧率 80%，次群/离群仅 **15%** —— hint 被主群占据，
它们拿不到好帧，也就积累不起证据（**鸡生蛋**）。

**服务调度**（RRM 风格）：单消旋器 = 单一资源，多分辨单元 = 待服务目标；
（注：这是**单通道架构**下的约束 —— 多通道形态下每通道自带消旋器，限制消失，见 §8.4）
优先级 **服务窗口 > 本帧匹配到的候选（它就是对端）> 最饿的未锁定候选 > LOCK 维持**。

> 修正记录：早期版本让"最饿的候选"无条件抢占，两个候选互相抢、都锁不住
> （`test_scene_switch` 暴露）；改为"匹配优先"后调度自然跟随帧流（机会主义）。

**调度后**：整体好帧率 **58%**；主群 65%；次群/离群 **36%**（调度前的 2.4 倍）。
`acquired=32 / lost=32` —— **LOCK/LOST 循环是多设备下的正常形态**（设备切换必然伴随
失锁重锁），指标看"每设备被服务的比例"而不是"最终剩几个 LOCK"。

**遗留**：离群设备仍差（帧量太少、轮转时轮不到）；进一步提升需要 MAC 辅助
（知道下一帧来自哪个对端 → 直接预置 hint）。

### 7.3 残余频偏容限实测（已执行 2026-10-01）

"两个状态至少要隔多远"由**残余频偏容限**决定。三个实验分别测：

**model 侧**（`run_residual_cfo.py`，SNR 18 dB，无消旋直接注入残差 δ）：

| δ | genie 定时（解调环节） | honest 全搜索同步 |
|---|---|---|
| ≤2 kHz | BER=0 | BER=0 |
| 4–40 kHz | **BER=0（无损）** | **sync_fail 100%** |
| 50 kHz | 崩（3.5e-1） | 崩 |

→ **解调容限 ~40–50 kHz**（与非相干判决容限 62.5 kHz 吻合）；
**全搜索同步容限仅 2–4 kHz**，且是**尖锐门限效应**（绝对门限对相干累积的 CFO 衰减过敏）。

**RTL 侧**（`run_rtl_residual.py`，用外部参数通道故意错配，20 帧/点）：

```
δ=0/2 kHz    100% 同步, BER=0        ← 无损
δ=4–10 kHz   85% → 65%              ← 缓慢退化
δ=15 kHz     40%
δ≥20 kHz     0%（崩）
```

→ **RTL 比 model 的 honest 判据宽容且是渐变的** —— 方案 C（L1 模判据）治好了"检测"，
后续环节（SFD 相干定界、采样判决）仍随 δ 平缓劣化。

**表征图**（`run_residual_viz.py`）：眼图（I 路）+ 星座（软值 + 理想参考），
δ=0/30/60 kHz 下 |soft| 均值 = 1.000 / 0.985 / **0.071**（解扩软值整体塌陷）。

### 7.4 固件在环：DPI-C（已执行 2026-10-01）

`observer_dpi.c`（与 `observer.py` 同结构的 C 实现）经 **DPI-C** 在仿真中被实时调用：
`mc_top_tb.sv` 在每次 `est_done` 把（估计值, 质量分子/分母）喂给它，LOCK 后经
**外部参数通道**接管消旋（`+DPI=1` 启用）。

**结果**（CFO=100 kHz，外部触发，20 帧）：调用 20 次 = EST 事件 20 次；
状态机轨迹 `SEARCH(2 帧) → VERIFY(1 帧) → LOCK(17 帧)`；LOCK 后 `inc=105520`
（≈100.6 kHz，真值 100 kHz）；链路 20/20、BER=0。

**意义**：决策器不必是 RTL 的一部分 —— **C/固件实现可在仿真中被实时调用并接管控制**，
这是 §4.3"两种落地形态"里的在线形态。

## 8. 多假设处理与分辨单元宽度

### 8.1 单元宽度（由 §7.3 的容限决定）

- **无损口径**：δ≤2 kHz（全宽 4 kHz）—— 太苛刻，不现实；
- **工程口径**：全宽取 **10–20 kHz**（δ=10 kHz 仍有 65% 可用率），边缘退化区靠重叠兜底；
- **状态数不按理论覆盖算**（铺满 ±192 kHz 需几十个单元），按**实际设备群数**算 ——
  主群合并成一个、离群各一个（这正是"状态数 ≪ 设备数"）。

### 8.2 重叠规则

- **必须有重叠**：边界退化区需要相邻单元兜底 → **步长 ≈ 全宽的一半**（5–10 kHz）；
- **但不是"铺网格"**：状态由观测**按群聚类**形成 —— 两群中心距 < 全宽时**主动合并**
  （残余仍在容限内），距 ≥ 全宽时各自成状态；
- 重叠的代价只是归属可能抖动（设备被两个状态都覆盖），不造成漏配。

### 8.3 多假设的三条路线（单消旋器的替代）

单消旋器一次只能服务一个分辨单元 = **时分**。三条路线：

| 路线 | 做法 | 代价 | 状态 |
|---|---|---|---|
| **时分 + 调度** | 现方案（§7.2） | 每单位服务时间减半 | ✅ 已实现并验证 |
| **top-2 顺序检验** | 估计器多输出一个次优假设；本帧失败则下一帧换它 | 近乎零硬件成本 | ⬜ 待做 |
| **双线并行** | 例化两个接收机，各带 A/B 参数处理同一份 IQ，各出码流（FCS 选优） | 见 §8.5（估计外置后可大幅降低） | ✅ **RTL 已验证**（`rx_dual` + `tb/rx_dual`） |

**双线的关键约束**：

- 分叉点应在 **MF 之后**（MF 与估计器共享一份）；
- 两路可能**同时解出帧**（同一帧被两个假设都解出）→ 需去重；
- 只覆盖 2 个假设；3+ 个分辨单元仍需叠加调度；
- **A/B 参数应取"分得开的两个群"的中心**（间隔 ≥ 全宽）—— 靠得近的群由 §8.2 的合并
  解决，两条规则互补。

**不饱和判断**：链路分析是偶发事件（网络结构稳定、设备参数不持续漂移），
架构上参数是"**保持**"的而非每帧重算；双线也可按需启用。

### 8.4a dapping 的定位澄清（2026-10-01）

**dapping（重叠波形的同时分离）不是本设计的核心 feature**，它只是多通道的一个
**附带能力**，真正用途是 —— **容纳参数偏离主群的设备（漂移/离群）**。
本设计**不涉及信道复用**（CDMA/多址那一套）：多通道的职责是
"主通道服务主群 + 第二通道兜住漂移"，不是"同时接收多个设备"。

**实测的能力边界**（`run_dapping.py`，两设备波形完全叠加）：

| Δf（旋性差） | 双路同时解出率 |
|---|---|
| 0–10 kHz | ~0%（两路都失败） |
| 25 kHz | 92% |
| **≥50 kHz** | **100%** |

同频时只有 ~55%（半数符号正确）—— DSSS 的 ~15 dB 处理增益（√32 倍）不足以完全
压制等功率干扰；此时唯一的分离维度是码正交，而它被半正弦成形的 ISI 削弱（`run_codebook`：
Walsh 码本只在 5–10 kHz 窗口带来 +4~8%，同频无增益）。

**结论**：分离靠**旋性差**而非码正交；码本替换是“锦上添花”，不是另一条分离维度。

### 8.4 通道数预算与替换策略

**"谁规定只能一个消旋器"**——单消旋器是**单通道架构**的结果，不是原理约束。
假设殊异 ⇒ 旋性不同 ⇒ **每通道自带消旋器**。验证（同一帧流、同一份 IQ）：

| 形态 | 消旋器 | devA | devB | devC | 整体 |
|---|---|---|---|---|---|
| 单通道·固定 | 1 | 100% | 0% | 0% | 65% |
| 单通道·调度（§7.2） | 1 | 80% | 20% | 25% | ~58% |
| **多通道·并行** | **N** | 100% | 100% | 100% | **100%** |

**通道数预算**（`run_channel_budget.py`；设备群长尾：主簇 68% + 次簇 17% + 离群 8% + 长尾 7%）：

| 分辨单元宽 W | 1 通道 | 2 通道 | 3 通道 | 拐点（边际<10%） |
|---|---|---|---|---|
| 10 kHz | 28% | 55% | 68% | 第 5 个 |
| 16 kHz | 61% | **78%** | 86% | **第 3 个** |
| 24 kHz | 68% | **85%** | 93% | 第 3 个 |

**关键洞察：通道数 × 单元宽度 ≈ 常数**。单元宽度由容限决定（无损 2 kHz / 工程 10–24 kHz）
—— **"降级工作"换来的正是通道预算的宽松**。"双通道即可"成立（W≈16–24 kHz 时覆盖 78–85%）。

**替换 / 合并策略**（把通道当缓存行）：

- **合并优先**：两通道 hint 间隔 < W → 同一分辨单元 → 合并、释放一个（**无损**，永远先试）；
- **替换**：新状态与所有通道都 ≥ W → 踢掉"近期命中率最低"者（物理层可见的收益度量）；
- **保留（pin）**：命中率最高者长期保留。推荐形态 = **主通道（pin）+ 可替换通道（flex）**。

替换事件其实稀疏（"链路分析不饱和"）—— 不需要精细缓存算法，粗判据足够。

### 8.5 RTL 实践：`rx_dual`

`rtl/rx/rx_dual.sv` 是双通道并行的落地形态：同一份 ADC/IQ 喂两条"旋性假设"
（A/B 两组参数），各出码流，`any_fcs_ok` 汇总。验证（`tb/rx_dual`，cocotb）：
同一份含 CFO=100 kHz 的 IQ ——**A 用正确消旋值解出、B 不消旋失败**；
以及"扫描量相位 → 直锁复用"的等价性（两通道都解出）。

#### 8.5.1 共享定时恢复（2026-10-01 第二轮，已完成）

把管线拆细后重新划边界：**相位/去交错可以共享，SFD 定界不能**。

```
ADC → rx_frontend（MF + 相位恢复 + 持续去交错）──┬── rx_chip_backend(旋性 A) ──> 码流 A
                        （**一份**）              └── rx_chip_backend(旋性 B) ──> 码流 B
```

- **共享依据**：帧到达的**定时（相位）**对所有通道相同（同一份 IQ），且
  "按定时抽取"与"复乘消旋"是可交换的线性操作 → 相位可共享、消旋可后移到去交错之后；
- **不可共享的依据**：SFD = 64 片**相干**相关，要求窗内相位一致，必须跑在
  **已消旋**码片上 → 每通道一份（`sfd_detect.sv`）。
- **消旋工作率降 8 倍**：从采样级（16 MHz）降到码片级（2 MHz）——
  面积不变（LUT 复用），动态功耗 ∝ 1/8。相位增量语义同步改为**每码片**
  （若手头是每采样值，×8）。

**新增/重写的 RTL**：`deinterleave.sv`（持续去交错：按固定相位抽片，不再中断）、
`sfd_detect.sv`（码片级 SFD 定界，吃已消旋码片）、`rx_frontend.sv`（MF + 相位恢复
+ 去交错）、`rx_chip_backend.sv`（消旋 → SFD → 解扩 → 解帧）。
`rx_backend` / `rx_top`（单通道路径）保持不变。

**相位 latching**：`rx_frontend` 只取 `preamble_sync` 的**相位输出**（码片端口悬空、
`frame_done=0`）。未消旋输入下它的 SFD 不触发 → 周期性超时重扫 → 码片流断续，
**不能**直接用它的码片输出；故用一个 latch 住相位的独立 `deinterleave`，码片流不再中断。

#### 8.5.2 一个必须记住的时序陷阱（调试实录）

**症状**：帧怎么都解不出（`fcs_ok=0`），但 SFD 定界位置看起来对。

**根因**：`frame_start` 的**发出拍**比"首个 PHR 码片"晚了一拍。
码片间隔 8 拍，若把"检测到 → 置 pend"与"下一个 `chip_dv` 拍才发出"写成两级，
则 `frame_start` 会与**第二个 PHR 码片**同拍 → `despreader` 的 32 片窗口整体晚 1 片
→ **全帧符号级错位** → 一帧也解不出。

**正确写法**（`sfd_detect.sv`）：检测拍**直接**置 `frame_start`（下一拍有效，
通常是片间隙），让紧跟的第一个片成为新窗口首片。

**调错用的分层证据**（已固化进 `tb/rx_dual` 的 `[检查]` 行，值得复用）：

1. **参考表自检**：`despread(期望码片) == 期望符号`？（先把"表"和"口径"钉死）
2. **片流相关**：RTL 消旋片流 vs 期望码片序列的归一化滑动相关 `r`
   （上限 = √片数）—— 判定前端/消旋是否完好；
3. **离线解扩**：用 RTL 片流自己解扩、**扫片级偏移 0..31** —— 片流若能解出，
   则问题必在"窗口/定界"而不在"信号"；
4. **RTL 实际输出**：与期望符号全偏移对齐。

第 3 步的"扫片级偏移"是关键：只看符号级偏移会漏掉 off-by-one 的窗口错位
（本次实测：正确偏移 20，RTL 用 21 —— 只差 1 片，符号全错）。

#### 8.5.3 每通道成本

| 形态 | 每通道内容 | 估算 |
|---|---|---|
| 完整 `rx_top` ×2 | 同步器（16 候选扫描）+ 消旋 + 解扩 + 解帧 | ~50 kbit |
| 共享 MF（第一版） | `cfo_rot` + `preamble_lock` + 解扩 + 解帧 | ~10 kbit |
| **共享定时（本轮）** | `cfo_rot`(**码片级**) + `sfd_detect` + 解扩 + 解帧 | ~10 kbit，**功耗 ∝1/8** |

**“估计外置”与“多通道”是同一件事的两面**：前者让每通道变便宜，后者才可负担。

## 9. 异常帧上报（baseband 的"元认知"）

问题：**baseband 能否自己发现"这一帧不在我 A/B 两个参数的覆盖内"？** 能——设施齐备：

| 职责 | 现成设施 | 实测 |
|---|---|---|
| 区分帧与噪声 | `preamble_detect`（短窗归一化延迟自相关） | 对 CFO 免疫，三 CFO 点 20/20，虚警 0.74% |
| 我锁上了吗 | `preamble_sync.detect` | — |
| 我解出来了吗 | `rx_deframer.fcs_ok` | — |

**判据**：`preamble_detect 触发 ∧ (未锁定 ∨ 锁定但 FCS 失败)` → 「异常帧」。

**上报内容**：配合 **I-13 前导缓冲**，上报的不是一个标志而是**那一段原始前导码片** ——
上层拿去任意分析（§5 的可插拔方案空间），得出新参数后经外部通道下发。
这是 **检测 → 上报 → 分析 → 下发** 的完整闭环，每一环都有落点。

**注意**：`preamble_detect` 有 0.74% 虚警，上报判据应加**连续确认**（M/N，同 §3.2）。

## 10. 遗留与开放问题

- **控制回路的稳定性**：后侧给 `phase_inc` 预置 + 单元自己也在估，两者如何避免打架
  （`ext_inc_en` 已提供切换，但"何时信任内部估计"的策略未定义）；
- **多参数扩展**：DC/IQ/定时何时纳入状态向量（当前只做 CFO）；
- **置信度的量化**：`q_floor/acquire_th` 的标定（可用 §7.1 的回放数据反推）；
- **卡尔曼升级**：把证据累积替换为状态空间滤波（§5.3），收益待评估；
- **I-13 上行缓冲**：异常帧上报（§9）与 SEARCH 态的全信息观测都依赖它 ——
  下一个该落地的 RTL 件；
- **top-2 顺序检验**（§8.3）：改动最小的多假设路线，待实现与验证；
- **双线的 ref 验证**（§8.3）：model 侧用两条链跑同一份信号，验证"各出码流、FCS 选优"的增益；
- **发射端协同**（用户提出，滞后）：TX 预补偿是对偶于本模块的"链路质量服务"，
  但需反馈/同步通道（ACK 捎带或网络同步），属跨层范畴。
