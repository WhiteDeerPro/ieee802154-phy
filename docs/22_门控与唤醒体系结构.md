# 22 门控与唤醒体系结构（Gating & Wake-up Architecture）

> 2026-10-03。目标：建立**数字侧门控/唤醒的体系语义**——低功耗以"**插入式**"为主
> （不动模块内部算法/微结构），把"暂停语义"逐模块定义清楚。验证采用"regression-as-ref"。
> 与 `docs/21`（机会清单）配套：本文档 = 架构与实施规则。

## 1. 三级功耗状态与转换

```
        ┌────────── 外部/SoC 唤醒 ──────────┐
        ▼                                   │
   [SLEEP] ──唤醒──▶ [LISTEN] ──pd_rise──▶ [ACTIVE(帧窗)]
        ▲               ▲                       │
        └── 长时间无帧 ──┴── 帧尾/超时(drain) ───┘
```

- **SLEEP**：整域（含模拟/RF）断电（power gating，SoC 决策）；数字侧仅保留"唤醒接口约定"。
- **LISTEN**：**只养 `preamble_detect`**（DEC=8、CFAR，最省）；**扫描器/后端/pbuf 全部门控**。
- **ACTIVE**：pd_rise 起链路全开，覆盖"本帧前导+数据窗"；帧尾（drain）后回落 LISTEN。
- **唤醒帧策略**（已定，docs/21 §10）：LISTEN→ACTIVE 转换后的**第一帧允许失败**（试探帧）。

## 2. 门控对象与暂停语义（逐模块定义——体系核心）

| 模块 | LISTEN 期 | 暂停语义 | 唤醒后恢复 |
|---|---|---|---|
| `preamble_detect` | **开**（职责所在） | — | — |
| `rx_matched_filter` | 关（随共享前端） | 移位线内容无意义 | 冷启动（线清） |
| `preamble_sync`(Csq) | **关** | 状态保持（扫描/相位候选）；**超时计时要按"有效拍"计或唤醒时重置** | 唤醒 = 扫描重启（本就每帧如此, RST_EN=1）；"用上次相位先试"是策略位 `SYNC_FASTPATH`（§10） |
| `preamble_buf` | 关（唤醒后开） | 内容可弃（重建） | 从唤醒起维护窗 |
| `deinterleave` | 关（帧窗开） | 帧外无有效数据，暂停无副作用 | — |
| `cfo_rot` ×2 | 关（帧窗开） | `dv` 门控已存在；`rot_load` 帧首载入 | — |
| `sfd_detect` ×2 | 关（帧窗开） | 帧外无副作用（drain 计数据有效拍） | — |
| `despreader` ×2 | 关（帧窗开） | **帧边界对齐**（片计数不可跨帧残留） | 帧首重置 |
| `rx_deframer` ×2 | 关（帧窗开） | 同上（与 despreader 同窗） | — |

**规则**：① 一切"帧外暂停"必须"无副作用"（帧窗由 `frame_start`/`drain` 界定）；
② 有"绝对时间"语义的计数（超时等）在门控期必须**冻结并按有效拍累积**或**唤醒时重置**；
③ 状态保持成本高的（pbuf/MF 线）直接弃重建；低成本的（sync 相位）保持做热启动。

## 3. 使能信号架构（"谁产出 en"）

- **中心化**：`rx_dual` 顶层新增**门控/唤醒控制小状态机**（PMU-lite）——
  输入：`ext_wake`（外部/SoC）、`pd_rise`、`frame_done`（任何通道）、`drain 超时`；
  输出：各模块的 `clk_en` / 模块 `en`（或直接供 gclk）。
- **模块侧**：暴露 `busy`（多数已有，§35 观测口）供 PMU 参考；**不新增算法逻辑**。
- **两级实现路径（插入式）**：
  - **路径 A（显式、可控）**：给子模块加 `clk_en` 端口，内部 `if (clk_en)` 包住时序块
    ——改动可见、易验证；适合先落地。
  - **路径 B（零侵入、终态）**：顶层用**标准 ICG**（latch-based，无 glitch）给子模块供
    `gclk`——子模块零改动；等价于"时钟树级插入"。**推荐作为终态**（路径 A 验证充分后切换）。

## 4. "插入式 vs 侵入式"——本文档的立场

- **插入式（采纳）**：门控/唤醒是**系统级事务**——在**边界**（端口/ICG）完成；模块内部
  保持"算法与微结构不变"，只保留既有的自然写法（`if(en)` 数据门控，利于工具推断）。
- **侵入式（不采纳，除特例）**：为省功耗重构模块内部（改架构/改位宽/改时钟方案）——
  只在"数据驱动"的明确收益项才做（如 **W=16→14**（notes §8 已证无损）、**A16→Csq**（已转正））。
- **理由**：插入式可**后加**、可**逐模块回退**、验证面小（regression-as-ref）；
  侵入式改一次伤一片，且与"ref 先行"流程冲突面大。

## 5. 验证策略（regression-as-ref）

- **功能等价（不需要新 ref）**：**"常开版"即 ref**——门控版在**全部回归流**上必须与
  常开版**逐帧一致**（边沿回归/主流量/mp1/影子对比原样跑通）；
- **门控专项**：构造"LISTEN→ACTIVE 转换"场景（人为拉长帧间隔/外部 wake 注入）——
  验证"试探帧丢弃 + 后续帧正常"、"sync 超时语义在门控下不漂移"；
- **收益代理（轻 ref）**：从 tb 事件流统计"**每模块有效拍/总拍**"与"**帧占空比**"——
  给出"门控收益上限"的结构性指标（无功耗工具时的口径）。

## 6. 关于"要不要 ref / RTL 怎么做"（问答存档）

- **需要 ref 吗**：功能面**不需要新模型**（回归当 ref）；收益面活动统计**已做**（§11.1）；
  **唤醒策略的锁定余量**（pd 唤醒后剩余前导 1588 采样够不够）**已完成**（notes §43：
  热启动（不清账）不可行；冷启动+对齐复位全绿）——"热启动要不要做" = 不做（按既定立场）。
- **RTL 实施顺序**：① PMU-lite 状态机（SLEEP 预留接口 / LISTEN / ACTIVE）+ `ext_wake`
  与 `pd_rise` 接线；② 路径 A 给 3 个"帧外缺口模块"（deinterleave/sfd/despreader）
  加 `clk_en` + sync/pbuf 的 LISTEN 门控；③ 回归（regression-as-ref）+ 活动统计；
  ④ 评估切路径 B（ICG 供 gclk）。

## 7. 门控时钟的行为约定（同源同频；"gating 住的模块如何表现"）

- **同源同频的门控时钟不是 CDC**（无相位漂移）——**不需要两级同步器**；但需四条约定：
1. **ICG 无 glitch**：标准 latch-based ICG（或让工具从 `if(en)` 推断）——不要"组合与"出 gclk；
2. **门控边界落在寄存器输出**：下游看到"冻结的稳定值"；
3. **有效性用 DV 语义**：门控期 `dv=0`（下游"看到沉默"而非"误收保持值"）——本设计
   全流式 + dv 伴行，**天然满足**；
4. **en 同域同步**：停/开都发生在"事务边界"（无在途数据）——本设计=帧外（gap 400+ 拍）。
- **被门控模块的"表现" = "输出冻结 + dv 拉低"**（对下游即"空闲"）。

### 8.1 "受限基线"实验（2026-10-03，回答"把基线也限制"的提议）

给帧窗加 `FE_WIN_DLY`（"前 N 片不用"）扫描 **snr6**：

| 配置 | snr6 |
|---|---|
| DLY=0（现状门控） | **15/60** |
| DLY=512 | **3/60** |
| DLY=1024 | **0/60** |

→ **前导片（尤其窗开后头几百片）在 6dB 下是"命门"**：任何"前 N 片限制"都会让基线
崩塌，**"公平受限对比"不可行**；也据此确认：门控的 −2/60 本质是**窗边界的拍级敏感性**
（临界帧差一两片即翻车），**非成片丢失**。判据维持 ≥15；`FE_WIN_DLY` 保留为实验工具
（默认 0）。下一步方向 = **PMU-lite 状态机（§10）**：帧窗从"数据门控"升为"时钟门控"，
并把 sync/pbuf/后端组纳入唤醒门（"热启动"一词的正名见 §10.1）。

## 9. 门控依赖与启用条件（"谁能关、关到什么条件、依赖谁"）

| # | 块 | 启用条件（谁决定） | 依赖 | 关闭时行为/代价 | 备注 |
|---|---|---|---|---|---|
| 1 | `preamble_detect` | 恒开（LISTEN 期唯一） | 无 | — | 最省侦听器（DEC=8/CFAR） |
| 2 | 共享前端（MF/同步/latch/去交错） | **帧窗**（pd_rise；`FE_WIN_*`） | pd | 窗外 `chip_dv` 停（v1 已做） | 相位维护（smp_cnt）不可关——例外 |

| 6 | **通道 A / B（整组：`cfo_rot`+`sfd`+`despreader`+`deframer`）** | **"该通道有活跃设备"**（配置/上层） | 共享前端 | 整组停（双份→单份） | **AB 独立；单设备只开一条** |
| 7 | **`cfo_rot`（消旋）** | "旋性需修正"（估计 CFO≠0 / 质量门限未满足） | 通道开 ∧ 需要 | bypass 直通 | **注意**：bypass ≈ 回退非相干路径——**SFD/相干窗要配套**（不可单方面关） |

| 9 | 观测/服务设施（events / DPI-C / VCD / dump） | 测试/调试模式 | 宿主 | 无 | 非功能路径，随开随关 |
| 10 | 状态保持域（sync 相位 / latch） | 随 sync | — | 初值策略用（§10 `SYNC_FASTPATH`） | "不可断"的例外（成本=漏电极小） |

**依赖链（谁在谁的后面）**：

```
pd ──▶ 帧窗 ──▶ 去交错/后端（整链）
        │
        ├──▶ pbuf 写（还 ∧ 上报策略：上层/unit 决定）
        └──▶ sync 唤醒（热启动：相位/latch 复用，待做）

通道选择（A/B）──▶ 该组后端（含消旋；消旋内部再有 bypass）
```

**规则**：① "整组开关"优先于"单模块开关"（通道 A/B 是天然整组）；
② 每个"可关"必须写明"关闭 = 功能等价回退路径"（如 bypass 消旋 = 非相干）；
③ "不可关"的只有两类：**pd（侦听职责）** 与 **相位维护/状态保持（连续性）**。

## 10. 唤醒状态机（剪枝：策略空间 → 两态 + 参数）

### 10.1 "热启动"正名（立场修正）

- 词源：`docs/16` §2.3 的 GNSS 类比（用历史状态砍搜索空间）。
- **修正**：唤醒的唯一入口是**能量（pd）**；"冷/热"之别不在硬件路径，而在扫描器唤醒后的
  **初值策略**——"先用上次锁定相位试一下"（策略位 `SYNC_FASTPATH`）。
- 此前 §8 把"热启动"引申成"预开窗拿更多前导"——那是把**策略位误读为时序机制**，作废；
  帧窗只有一种开法：pd_rise 开窗（§8 已实测其边界行为）。

### 10.2 剪枝（为什么只剩两态）

1. **拓扑钉死（不可门集）**：`MF → pd` 两块必须常开——pd 吃 MF 输出，而 pd 是全部门控的
   唯一参考事件源。⇒ 其余每块的"开时机"只能是 pd_rise 的单调函数。
2. **事件量化**：运行时可用事件只有 {pd_rise, 窗尽/超时}。⇒ 合法门控转移点 = 2 ⇒
   **状态字母表 = {S_LST, S_WIN}**（+ S_OFF 预留 SoC 断电）。
3. **组等价**：sync / pbuf / 后端组 A/B 的开条件互不依赖（都只依赖 pd_rise + 各自策略位）
   ⇒ 并行独立门控，无需嵌套/优先级 ⇒ 策略空间坍缩为
   **1 个时序参数（WIN_LEN）+ 4 个配置位**。
4. **"后端懒开"分支被否决**：SFD 定界要"已消旋码片"的 64 片相干窗（含前导尾）；
   `cfo_rot` 的相位零点约定在**帧首 load**（n=0 起算）——错过帧首后端输出全错。
   ⇒ 后端开点被数据流钉死在 pd_rise 附近，**无普适懒开点**；自由度只在**通道级**。

### 10.3 状态图与门控集合

```
             ext_wake               pd_rise              窗尽（无锁/超时）
  [S_OFF] ─────────────▶ [S_LST] ─────────────▶ [S_WIN] ───────────────▶ [S_LST]
      ▲                     ▲                      │ │
      └── SoC 决策 ──────────┘                      │ └─ pd_rise ─▶ 窗重启（连帧 linger）
                                                     └───（无需额外状态）
```

| 块 | S_LST | S_WIN | 语义 |
|---|---|---|---|
| MF、pd | 开 | 开 | 不可门（拓扑） |
| smp_cnt / 相位维护 | 开 | 开 | 连续性（"不可断"） |
| sync（扫描器） | **关（冻结）** | 开 | 唤醒 = 扫描重启（与现状 RST_EN=1 等价） |
| pbuf | 关 | 按 `PBUF_EN` | 收集策略（预告式） |
| 后端组 A | 关 | 按 `CHAN_EN_A` | 整组（消旋+SFD+解扩+解帧） |
| 后端组 B | 关 | 按 `CHAN_EN_B` | 独立于 A |

### 10.4 参数表（全部可配）

| 参数 | 默认 | 语义 | 供给方 |
|---|---|---|---|
| `WIN_LEN` | 70000（帧 69120+余量） | 窗长（帧窗+连帧 linger 合一） | 上位机/配置 |
| `CHAN_EN_A/B` | 1 / 1 | 通道整组使能（单设备 = 1/0） | 配置 |

（`FE_WIN_DLY` 仍是实验旋钮，不属运行策略。）

### 10.5 PPA 口径

- **新增逻辑**：状态位 + 17b 窗计数器 + 译码（≈10² cells 量级；待 yosys 复核）。
- **收益主体**：LISTEN 期关掉 **sync 扫描器**（6.5k cells 级）与两条后端组的时钟/翻转；
  单设备 `CHAN_EN=1/0` 再省半条后端。
- **代价**：sync"唤醒=扫描重启"与现状 RST_EN=1 行为等价（本就每帧 pd_rise 重启）——
  非新增代价；`SYNC_FASTPATH=1` 的初值设施可复用现有 `scan_phase`/latch（实施时核对保持语义）。

## 11. 门控实况对照与状态循环（2026-10-03 夜，量化审计）

### 11.1 机制 vs 决策：活动统计实测（tb `+STATS`）

问题：门控是否"太偏模块侧、缺 PMU/ICG 侧"？用层次引用只读的活动统计实测：

| 场景 | 总拍 | `fe_win` 占 | `chip_dv` 占 | `sync` 处理拍 | FRMA |
|---|---|---|---|---|---|
| snr20 连续流（帧周期 15348） | 920,860 | **99.97%** | 12.48% | 100% | 60/60 |
| listen1 长 gap=50k（帧周期 64946） | 3,896,789 | **98.7%** | 12.34% | 100% | 60/60 |

**读数**：`FE_WIN_LEN=70000`（按最大帧 69120+余量设定）≥ 实测帧周期 → **帧窗几乎恒开、
`chip_dv` 无压制**（12.3%≈码片节拍 1/8——是"数据节拍"而非"帧内数据"占比）——
**v1 帧窗机制已在位（en 通路 / dv 语义 / 下游自然停），但"关断决策"未生效：实测节电增益 ≈ 0**；
`sync`（6.5k cells 级）与后端全时运行。→ **用力点应从"模块侧机制"转向"PMU 侧关断决策
+ ICG 时钟级"**（与 §3 设计一致；当前只是停在"机制已铺、决策缺位"的中间态）。改进方向（按成本）：

- a) 窗长按实际流参数化（最小改动，长 gap 场景立刻见效）；
- b) 事件驱动关窗（帧尾 `drain` 提前关 + linger 超时兜底）；
- c) PMU-lite 两态机（§10.3）——`sync` 关闭的正确性已由"对齐复位"实验保障
  （关 3–513 拍冷启全绿，notes §43）；ICG（路径 B）随后切换。

### 11.2 门控决策树（事件 → 条件 → 动作）

```
[SoC ext_wake] ──▶ S_OFF→S_LST（整域上电；只养 MF+pd+smp_cnt）
      │
pd（常开，唯一事件源）
      │ pd_rise
      ├─▶ scan_rst：sync 扫描重启（每帧；§10.3）
      ├─▶ s_win 置位：开帧窗（WIN_LEN / 或"事件驱动关"改进项）
      │      ├─▶ deint.en ─▶ chip_dv ─▶ 后端组（CHAN_EN 整组）
      │      ├─▶ pbuf 写（按 PBUF_EN 策略）
      │      └─▶ sync.en=1（S_WIN 期；S_LST 期关 + 唤醒冷启）
      └─▶ pbuf.trig（帧到达快照）

[关断] 窗尽 / 帧尾 drain / linger 超时 ─▶ s_win 清零 ─▶ 各 en 落回 S_LST 集合
[对齐] 冷启动复位（wake_clr）仅当 k%16==0 发出（"对齐复位器"；notes §43）
```

### 11.3 状态循环：现状 vs 目标

- **现状**：`pd_rise → 开窗(70000) →（窗尽）关`——窗尽几乎永不发生（逐帧重置）⇒ **恒开**（11.1 实测）。
- **目标**：`S_LST ↔ S_WIN` 两态（§10.3），关断由**事件**（drain / linger 超时）与状态决定；
  `S_LST` 集合 = 只养 MF+pd+smp_cnt（+ 对齐复位器）；`S_WIN` 集合 = 全开。
- **判据**：任何关断不得伤害"帧内数据"（regression-as-ref + listen1 类长 gap 场景复核）。
