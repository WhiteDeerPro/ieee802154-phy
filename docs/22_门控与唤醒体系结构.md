# 22 门控与唤醒体系结构（Gating & Wake-up Architecture）

> 2026-10-03。目标：建立**数字侧门控/唤醒的体系语义**——低功耗以"**插入式**"为主
> （不动模块内部算法/微结构），把"暂停语义"逐模块定义清楚。验证采用"regression-as-ref"。
> 与 `docs/21`（机会清单）配套：本文档 = 架构与实施规则。

## 1. 三级功耗状态与转换

```
        ┌────────── 外部/SoC 唤醒 ──────────┐
        ▼                                   │
   [SLEEP] ──唤醒──▶ [LISTEN] ──pd_rise──▶ [ACTIVE(帧窗)]
        ▲               ▲                       │
        └── 长时间无帧 ──┴── 帧尾/超时(drain) ───┘
```

- **SLEEP**：整域（含模拟/RF）断电（power gating，SoC 决策）；数字侧仅保留"唤醒接口约定"。
- **LISTEN**：**只养 `preamble_detect`**（DEC=8、CFAR，最省）；**扫描器/后端/pbuf 全部门控**。
- **ACTIVE**：pd_rise 起链路全开，覆盖"本帧前导+数据窗"；帧尾（drain）后回落 LISTEN。
- **唤醒帧策略**（已定，docs/21 §10）：LISTEN→ACTIVE 转换后的**第一帧允许失败**（试探帧）。

## 2. 门控对象与暂停语义（逐模块定义——体系核心）

| 模块 | LISTEN 期 | 暂停语义 | 唤醒后恢复 |
|---|---|---|---|
| `preamble_detect` | **开**（职责所在） | — | — |
| `rx_matched_filter` | 关（随共享前端） | 移位线内容无意义 | 冷启动（线清） |
| `preamble_sync`(Csq) | **关** | 状态保持（扫描/相位候选）；**超时计时要按"有效拍"计或唤醒时重置** | 热启动：上次锁定相位先试 |
| `preamble_buf` | 关（唤醒后开） | 内容可弃（重建） | 从唤醒起维护窗 |
| `deinterleave` | 关（帧窗开） | 帧外无有效数据，暂停无副作用 | — |
| `cfo_rot` ×2 | 关（帧窗开） | `dv` 门控已存在；`rot_load` 帧首载入 | — |
| `sfd_detect` ×2 | 关（帧窗开） | 帧外无副作用（drain 计数据有效拍） | — |
| `despreader` ×2 | 关（帧窗开） | **帧边界对齐**（片计数不可跨帧残留） | 帧首重置 |
| `rx_deframer` ×2 | 关（帧窗开） | 同上（与 despreader 同窗） | — |

**规则**：① 一切"帧外暂停"必须"无副作用"（帧窗由 `frame_start`/`drain` 界定）；
② 有"绝对时间"语义的计数（超时等）在门控期必须**冻结并按有效拍累积**或**唤醒时重置**；
③ 状态保持成本高的（pbuf/MF 线）直接弃重建；低成本的（sync 相位）保持做热启动。

## 3. 使能信号架构（"谁产出 en"）

- **中心化**：`rx_dual` 顶层新增**门控/唤醒控制小状态机**（PMU-lite）——
  输入：`ext_wake`（外部/SoC）、`pd_rise`、`frame_done`（任何通道）、`drain 超时`；
  输出：各模块的 `clk_en` / 模块 `en`（或直接供 gclk）。
- **模块侧**：暴露 `busy`（多数已有，§35 观测口）供 PMU 参考；**不新增算法逻辑**。
- **两级实现路径（插入式）**：
  - **路径 A（显式、可控）**：给子模块加 `clk_en` 端口，内部 `if (clk_en)` 包住时序块
    ——改动可见、易验证；适合先落地。
  - **路径 B（零侵入、终态）**：顶层用**标准 ICG**（latch-based，无 glitch）给子模块供
    `gclk`——子模块零改动；等价于"时钟树级插入"。**推荐作为终态**（路径 A 验证充分后切换）。

## 4. "插入式 vs 侵入式"——本文档的立场

- **插入式（采纳）**：门控/唤醒是**系统级事务**——在**边界**（端口/ICG）完成；模块内部
  保持"算法与微结构不变"，只保留既有的自然写法（`if(en)` 数据门控，利于工具推断）。
- **侵入式（不采纳，除特例）**：为省功耗重构模块内部（改架构/改位宽/改时钟方案）——
  只在"数据驱动"的明确收益项才做（如 **W=16→14**（notes §8 已证无损）、**A16→Csq**（已转正））。
- **理由**：插入式可**后加**、可**逐模块回退**、验证面小（regression-as-ref）；
  侵入式改一次伤一片，且与"ref 先行"流程冲突面大。

## 5. 验证策略（regression-as-ref）

- **功能等价（不需要新 ref）**：**"常开版"即 ref**——门控版在**全部回归流**上必须与
  常开版**逐帧一致**（边沿回归/主流量/mp1/影子对比原样跑通）；
- **门控专项**：构造"LISTEN→ACTIVE 转换"场景（人为拉长帧间隔/外部 wake 注入）——
  验证"试探帧丢弃 + 后续帧正常"、"sync 超时语义在门控下不漂移"；
- **收益代理（轻 ref）**：从 tb 事件流统计"**每模块有效拍/总拍**"与"**帧占空比**"——
  给出"门控收益上限"的结构性指标（无功耗工具时的口径）。

## 6. 关于"要不要 ref / RTL 怎么做"（问答存档）

- **需要 ref 吗**：功能面**不需要新模型**（回归当 ref）；收益面**需要一个"活动统计"
  小实验**（可后补）；**唤醒策略的锁定余量**（pd 唤醒后剩余前导 1588 采样够不够）
  **需要一次模型实验**——但它独立于本文档，可后补（结论只影响"热启动要不要做"）。
- **RTL 实施顺序**：① PMU-lite 状态机（SLEEP 预留接口 / LISTEN / ACTIVE）+ `ext_wake`
  与 `pd_rise` 接线；② 路径 A 给 3 个"帧外缺口模块"（deinterleave/sfd/despreader）
  加 `clk_en` + sync/pbuf 的 LISTEN 门控；③ 回归（regression-as-ref）+ 活动统计；
  ④ 评估切路径 B（ICG 供 gclk）。

## 7. 门控时钟的行为约定（同源同频；"gating 住的模块如何表现"）

- **同源同频的门控时钟不是 CDC**（无相位漂移）——**不需要两级同步器**；但需四条约定：
1. **ICG 无 glitch**：标准 latch-based ICG（或让工具从 `if(en)` 推断）——不要"组合与"出 gclk；
2. **门控边界落在寄存器输出**：下游看到"冻结的稳定值"；
3. **有效性用 DV 语义**：门控期 `dv=0`（下游"看到沉默"而非"误收保持值"）——本设计
   全流式 + dv 伴行，**天然满足**；
4. **en 同域同步**：停/开都发生在"事务边界"（无在途数据）——本设计=帧外（gap 400+ 拍）。
- **被门控模块的"表现" = "输出冻结 + dv 拉低"**（对下游即"空闲"）。

## 8. 实施记录 v1：帧窗门控（2026-10-03）

- **改动**：`deinterleave` 加 `en`（`chip_dv <= (even|odd)&en`，**smp_cnt 照走——相位不丢**）；
  `rx_frontend` 产生帧窗（`pd_rise` 开窗 `FE_WIN_LEN=70000` 拍；当拍组合放行）；
  `g_direct`（测试模式）`fe_win=1'b1`。**一处门控 → sfd/despreader/后端自然停**（插入式）。
- **验证（regression-as-ref）**：主 bin 冒烟 60/60；**全回归 ALL PASS**（snr6 判据 16→15）。
- **代价（如实记录）**：6dB 边界 **17→15/60（−2 帧）**；定位过程：实验 A（窗≈恒开）
  仍 15、实验 B（`.en=1'b1`）回到 17 → 损失来自"**帧窗 × 低 SNR pd 抖动期**的交互"
  （非相位破坏；完全机制未定位——用户裁定"不深挖"）；**采纳限制放宽至 ≥15**。
- **pending**：活动拍统计（收益量化）；LISTEN 期 sync/pbuf 门控（需唤醒语义）；路径 B（ICG）。

### 8.1 "受限基线"实验（2026-10-03，回答"把基线也限制"的提议）

给帧窗加 `FE_WIN_DLY`（"前 N 片不用"）扫描 **snr6**：

| 配置 | snr6 |
|---|---|
| DLY=0（现状门控） | **15/60** |
| DLY=512 | **3/60** |
| DLY=1024 | **0/60** |

→ **前导片（尤其窗开后头几百片）在 6dB 下是"命门"**：任何"前 N 片限制"都会让基线
崩塌，**"公平受限对比"不可行**；也据此确认：门控的 −2/60 本质是**窗边界的拍级敏感性**
（临界帧差一两片即翻车），**非成片丢失**。判据维持 ≥15；`FE_WIN_DLY` 保留为实验工具
（默认 0）。下一步方向（"热启动拿更多前导"）= 用上次状态**预开窗**——归入唤醒语义的
热启动项。
