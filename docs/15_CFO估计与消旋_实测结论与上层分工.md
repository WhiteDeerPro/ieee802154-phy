## 2. 为什么必须修：物理与失效模式

### 2.1 三个时间尺度

前导 256 码片 = 128 µs。CFO 造成的相位旋转在这个窗口内积累：

- **7.8 kHz** = 128 µs 转一圈 → 相干积分的判据容限；
- **62.5 kHz** = 单个码片间隔内可容忍的非相干判决容限；
- **500 kHz** = 跨 2 码片差分（1 µs）的无模糊上限，也是 `INC_LIMIT`（取 500 kHz）的依据。

标准晶振 ±80 ppm → 2.4 GHz 下 ±192 kHz，**是 7.8 kHz 的 25 倍** —— 不修必死。
（实测：96 kHz = 12.3 圈/前导，相干积分峰完全塌陷。）

### 2.2 两种失效模式（实测）

| 模式 | 表现 | 实测点 |
|---|---|---|
| **A 同步环失效（主导）** | CFO 让前导相关峰塌陷，同步锁不上 → 全链崩 | 50 kHz 起不修 BER 4.37e-1 |
| **B 判决环退化（次要）** | 同步侥幸锁上后，星座旋转导致判决错 | 高阶 CFO 下不修 BER 5.8~6.3e-1 |

修 CFO 的**主要收益在同步**：消旋后前导相关峰幅度恢复 5.5 倍
（`model/out/rtl_cfo/`）。

### 2.3 与 SFO 的对比

同一晶振偏差的两个后果，但修复成本完全不同：

- **CFO**：公共相位，估一次、消旋一次，持续成本 = 每采样一次复乘（4 乘 2 加）；
- **SFO**：采样时刻漂移，必须重采样/插值（Farrow），成本高一个量级。

容限也差一个量级：**CFO 3.3 ppm vs SFO 58 ppm** —— 该优先修 CFO。

## 3. 算法：联合估计与三个坑

### 3.1 循环依赖 → 把对齐点和频偏一起搜

**不能"先同步再估频偏"**：CFO 让复相关峰塌陷，5 kHz 起窗口内 argmax 就开始选错
（实测 50 kHz 时峰位偏 17 采样 = 2.1 码片）→ 取到的码片软值全错 → 差分输出全是噪声。
这是循环依赖：同步被 CFO 打瞎了，却又要用它去估 CFO。

**破法**：对候选对齐点 p 逐个取码片软值 v[m]，除掉已知前导的定点软值 c_ref[m] 得
`z[m] = v[m]·conj(c_ref[m])` —— z 应是一串纯相位（CFO 造的）。
判据用**相位一致性** `Q = |Σd| / Σ|d|`（d = 跨 2 码片的差分）：
对齐对 → 全同相 → Q≈1；对齐错 → 乱 → Q≈0。
不用任何先验定时，扫一遍候选取 Q 最高者即可。

### 3.2 三个坑（都实测踩过）

1. **差分必须跨 2 个码片（同一路）**：O-QPSK 的 I/Q 半码片错位让相邻码片的采样间隔
   在 12/4 采样之间交替，相位差不等、不能相干平均；跨 2 码片走同一路，间隔恒定 1 µs。
2. **必须除掉成形串扰**：码片软值自带 ±18.09° 的结构性相位（偶数码片采样点上，
   前一个 Q 码片的尾巴 g[11]=1.3066 漏进虚部，主分量 g[7]=4.000，
   atan(1.3066/4.000)=18.09°），远大于 CFO 造的几度。用理想前导软值 c_ref 做复数除法除掉。
   （残留的确定性偏置 ≈ 858 Hz，见 `docs/08` I-4，对功能无影响。）
3. **不要跳过 c_ref 的定点化**：c_ref 必须是"理想前导经同一成形链"的软值，
   直接存 ±1 会丢掉串扰项、丢掉上面那 18°。

### 3.3 精度与无模糊范围

- 无模糊：±500 kHz（覆盖标准 ±192 kHz 的 2.6 倍）；
- 模型侧估计质量（`cfo_fix/report.md` 表格）：


## 4. RTL 实现与实测

### 4.1 三个模块

- `rtl/rx/legacy/cfo_est.sv` —— 8 个相位候选并行做差分相关，用 |acc|² 当相位一致性判据选最佳；
  对齐点与频偏一次搜完，**不依赖任何上游同步**；
- `rtl/rx/legacy/cordic_atan2.sv` —— 16 级向量模式 CORDIC 求 arg(acc)，只用移位和加减、无乘法器；
  内置象限预处理（否则 ±99.9° 收敛域装不下 ±180° 的差分相位）；
- `rtl/rx/backend/cfo_rot.sv` —— 24 位相位累加器 + 256 点 cos/sin LUT + 一次复乘/采样；
  接口 `load` / `phase_inc[23:0]` / `phase_off[23:0]`。

**位宽**：输入 21 bit（与 `rx_matched_filter` 同宽）；z 右移 16 保 21 bit；d 右移 6；
acc 48 bit；CORDIC 输入取 `acc>>12`。

### 4.2 实测（VCS，无噪）

```
 CFO(k)   p_hat    f_est(k)     修前BER     修后BER
     0       7      -0.003    1.00e-09    1.00e-09
    50       7      50.000    4.20e-01    1.00e-09
    96       7      96.001    5.36e-01    1.00e-09
   300       7     299.991    7.41e-01    1.00e-09
   450       7     449.989    7.95e-01    1.00e-09
```

有噪条件（+20 dB）RTL 偏差 0.03~0.05 kHz。修后 BER 与无 CFO 时同水平。

### 4.3 实现层面的五个坑（都已修）

1. **ROM 索引必须用码片序号**：候选的偶链收 m=0,2,4,… 要用 `2*mc_e` 索引，不是"第几片"；
2. **偶/奇链计数器必须分开**：同一候选既收偶片又收奇片，共用一个计数器会互相踩；
3. **跳过 t=3 槽位**：候选 7 的奇数序列从 t=3 开始，而 `off[2j+1]=16j+19` 最小 19 ——
   t=3 是"码片 −1"，收进来整条奇链错位一片；
4. **CORDIC 内部位宽要留够**：|acc| 达 2^32 且迭代中涨 1.65 倍，余量不足会回绕
   （实测 18° 被算成 68.6°）；
5. **CORDIC 要做象限预处理**：每级累计旋转上限 99.9°，直接喂第二/三象限会转不过去
   （300 kHz 的 108° 差分相位曾被折叠成 277 kHz）。

## 5. 触发源：当前最大遗留

### 5.1 结论链（三次探索，详见 `docs/08` I-6）

1. **独立检测器**（`rtl/rx/frontend/preamble_detect.sv`，短窗归一化延迟自相关）：
   对 CFO 完全免疫、三 CFO 点 20/20，但首触发偏移 460±10 稳定却非零，
   接 `cfo_est` 需要对齐参数；**四次调参尝试全部失败** ——
   对齐不是单一偏移量，而是（cref 索引 + 服务窗相位 + 预热 + t==3 补丁）的联合约定。
2. **改用 `preamble_sync.detect`**（偏移 538±1，精度高一个量级）：发现相位约束
   `(触发相位) ≡ 1 (mod 16)`；加延迟对齐后仍不收敛。
3. **dump 内部状态反推**（对齐点、cref 索引、服务点的拟合关系）：仍有未识别约束。
   结论：**调参不是正确路径，要重写 `cfo_est` 的 COLLECT 段**（`docs/08` I-17）。

### 5.2 方案 C（已实施）：判据改复相关模

根因比上面更底层：`preamble_sync` 的块间自相关判据是 `Re(Σ v·conj(v'))`，
带 `cos(ω×256)` 因子 —— CFO=100 kHz 时 cos = **−0.81（反相）**，
永不过正门限 ⇒ **检测死锁**。这解释了"检出率随 CFO 非单调"。

修法：判据量改为 L1 模 `|accR| + |accI|`（免开方/免除法）。
ref 验证（`run_preamble_mag.py`）：实部判据在 50 kHz 就崩（2/20），模判据全 CFO 20/20、
偏移恒定 824、抖动 0。

### 5.3 端到端效果与剩余问题

```
 CFO      方案C前      方案C后
   0     50/50·BER0   48/50·BER 4e-2
 100 kHz    0/50        25/50
 200 kHz    0/50        25/50
 450 kHz    0/50        26/50
```

**检测漂移已消除**（DET 位置三 CFO 点稳定在 538/mod256=26）。

剩余两个问题（`cfo_trigger/report.md` §9.5）：

1. **冷启动靠碰运气**：估计序列前 14 帧全乱（被质量门控拒绝）→ 第 15 帧才通过 →
   采纳 → 消旋 → 之后收敛。需要"未消旋也能估得准"的路径，或更快的收敛机制；
2. **收敛后偶发失败**：每 ~10 帧一次（bad estimate + 该帧同步失败）。
   `EST_REQ_QUAL` 不能关（关后全崩）。

→ 落成 `docs/08` **I-17**（重写 COLLECT 段）。

## 6. 上层分工：旋性的发现 / 记忆 / 匹配

### 6.1 架构决策（`docs/12`）

**Zigbee 单元只做消旋；旋性的发现、记忆、匹配、淘汰放上层（或转发出去做）。**
理由：模式是"有限集且切换不频繁"的网络属性，不是物理层原语；
放上层可以用任意复杂度（FFT、查表、学习），且不占用单元面积。

### 6.2 接口形状

```
单元 → 上层:  前导期码片软值序列（256 项 × 2(I/Q) × 21 bit ≈ 10.5 kbit）+ 帧到达标记
上层 → 单元:  phase_inc（每采样相位增量）+ phase_off（帧起点相位）
```

### 6.3 已具备的能力

- **FFT 发现**（`run_cfo_fft.py`）：256 点码片级 FFT（等效采样率 = 码片率 2 MHz），
  bin 7.8125 kHz、无模糊 ±1.00 MHz、全 CFO 20/20、抖动 0；
  对照"差分法冷启动需 ~15 帧碰运气"。
- **模式库**（`model/upper/patterns.py` + `run_pattern_lib.py` / `run_pattern_link.py`）：
  96% 命中、0 误配、**29 倍加速**；3 设备交替场景 PER 32.5%→0%。

### 6.4 待办 issue（`docs/14`）

## 7. 遗留与"明确不做"

**遗留**（详见 `docs/08`）：

- **I-4** 858 Hz 固有偏置：cref 串扰残留，对系统无影响（0.36 ppm ≪ ±80 ppm），接受；
- **I-5** `phase_off` 输出未生效：与 I-17 一并处理（重写 COLLECT 段时修正或删除该端口）；
- **I-7** 判决与置信度体系：架构性，待统一。

**明确不做**（各有实测依据）：

- ❌ **RTL 内 FFT**：转发上层即可（`docs/12` §2）；
- ❌ **RTL 内按节点记忆 / EMA / 16 节点表**：与 `docs/12` 分工冲突，归上层模式库；
- ❌ **2048 点 FFT**：前导只有 256 码片，实际是 256 点（等效 2 MHz 采样）；
- ❌ **投票累积器 / 多次一致采纳**：实测在当前架构下无效（估计 bin 分散）、
  或一开就崩（`USE_VOTE=1'b0` 保留为实验开关）；
- ❌ **靠加长累积窗/多块平均改善低 SNR 同步**：物理上不可行（`docs/08` I-3）。
