## I-1 [待讨论·优先] 多径信道

**现象**：链路未系统验证多径下的表现。802.15.4 典型室内信道 RMS 时延扩展 10–100 ns，
对应 0.02–0.2 码片，弱多径即可让 Raised-cosine 前的 O-QPSK 产生码间串扰。

**为什么重要**：任何无线通信都要面对；数字基带侧的可选手段包括
（a）判决反馈/线性均衡，（b）前导期信道估计 + 频域补偿，
（c）加大匹配滤波抑制或（d）依靠 DSSS 的处理增益直接抗。

**现状**：`model/baseband/equalization.py` 有浮点参考实现，
`model/experiments/run_multipath_eq.py` 有实验脚本，但没有 RTL 侧或全链协同验证。

**待决**：（1）本项目要不要做数字均衡，还是靠 DSSS 增益硬扛？
（2）若做，用前导 LS 估计（前导已知，成本可控）还是盲估计？

**优先级**：中高（功能性缺口，非缺陷）。

## I-2 [已定性·达标·结案] 低 SNR 同步性能

**现象**：检出率随 SNR 下降（顶层集成链，100 帧/点，CFO=10kHz）：

```
SNR(dB):   +20  +18  +15  +12  +10   +5    0
检出:      99%  99%  94%  83%  74%   72%   8%
```

**目标工作点**（README 链路预算）：−85 dBm 灵敏度目标 → 噪声底 −103 dBm（kTB −111 + NF 8）
→ **可用码片 SNR ≈ 18 dB**。（9.03 dB 是扩频增益，不是工作点；解调需求仅 ≈ −1 dB @BER=1e-3。）

**结论**：**+18 dB 实测 99% 检出、PER = 1%，恰好满足标准 PER ≤ 1% 要求**。
即当前数字基带在 −85 dBm 目标上**达标**。

**根因（已定性）**：更低 SNR 的下降与 CFO 模块无关（基础链无 CFO/rot/est 同样降：
+10 dB 18/20、+5 dB 16/20、0 dB 7/20），本质是前导同步的相干累积在低 SNR 下的
固有判决能力（判据基于 32 片块间相关）。README 链路预算已预判："受限于同步/CFO 而非解扩"。

**影响**：−85 dBm 目标达成；若要向 CC2530 级（−97 dBm，即再低 12 dB）下探，
则同步是主要障碍（−97 dBm → 码片 SNR ≈ 6 dB，此时检出仅 ~70%）。

**候选方案**（仅在下探灵敏度时需要）：
（a）加长累积窗（代价：锁定延迟）；
（b）多块联合判决；（c）提高前导利用率（当前仅 4/8 块参与锁定门限）。

**优先级**：低（目标工作点已达标）。

## I-3 [已定性·低·结案] +20 dB 下 ~1% 随机帧丢失

**现象**：100 帧/点的高 SNR 测试中，1–2 帧失败（fcs_ok 差 1–2%）。

**根因（已定性）**：随机误锁率，不是特定帧的确定性缺陷：
- 4 个 CFO 点失败的是同一帧（f34）→ 因为 seed 固定、帧序列相同；
- 改 seed（2/3/4）后失败率变为 1%/0%/2%，与其它 seed 无关；
- dump f34 显示：锁定两次（lphase 12/11，理论应 9），即**选到邻近错误候选**（差 2–3 采样），
  导致 SFD 相关峰值仅 6e12 << 门限 3e13。

**机制**：噪声让"错误候选的 bestR 暂时超过正确候选"，而轴判别只拦"轴互换"、
拦不住"邻近候选"，锁定即落在 1–3 采样偏移上 → 去交错边界错 → SFD 崩。

**为什么现有判据拦不住（定量）**：正确候选与差 1 采样候选的块间共轭积差异仅 **3.29%**
（实测 6.566e4 vs 6.350e4），而单块（32 片）噪声波动：

```
SNR=+20dB: 2.50%   |  SNR=+10dB: 7.91%   |  SNR=+5dB: 14.06%
```

前导仅 8 块可用 → 平均 8 块后噪声降至 0.88%（+20dB）/ 2.80%（+10dB），
仅在 +20dB 能可靠区分，+5dB 需 ~18 块平均 —— **物理不可行**。
且当前 `bestR = max over 历次块` 用极值，会比均值再放大噪声 → 这是"模式识别需求"的本质困难。

**关于"锁定/退锁模式识别"的讨论**（用户提出）：理想方案是跟踪多个候选的得分时序，
识别"真帧到达"的特征模式（正确候选得分阶跃后保持高位）而非单点判决。
实现复杂度高（需多假设跟踪 + 确认/否认计数 + 退锁策略重设计），且受上述信噪比 
限制上限很低，**归为本 issue 不再推进**。

**影响**：1–2% 帧丢失（+20 dB）；随 SNR 降低此率升高（+10 dB 降至 ~35% 丢失，
与 I-2 同源）。

**候选方案**：
（a）`ready` 判据从"连续 2 块"提到"连续 3 块"（代价：锁定延迟 +256 拍，前导余量足够）
   —— 用户评估后**不做**（收益有限，且未触及根本）；
（b）锁定时要求 bestR 超过次优候选一定比例（tie-break 硬化）；
（c）`bestR` 从"单块极值"改为"多块平均"或"延长块到 64 片" —— 能把噪声波动从 2.5% 降到
   1.77%（+20dB），但代价是锁定延迟 +256 拍、且对 CFO 残留更敏感（相位跨度翻倍）；
（d）在候选分辨率上做模板类判据（受"帧对齐未知"限制，见 docs/07 §4.6）。

**优先级**：低-中（与 I-2 同源，可一并处理）。**经评估暂不做**：所有方案要么收益 
限于高 SNR（物理上无法覆盖低 SNR），要么引入可观的锁定延迟/CFO 敏感度代价。

## I-4 [已定位·低·结案] cfo_est 的固有频偏偏置（~858 Hz）

**现象**：无 CFO 时 `phase_inc` 估计出 ~900（等效 858 Hz）；1 kHz 时估 1973 ≈ 1049+923。

**根因（已定位）**：`c_ref_rom.svh` 存的是"理想前导 MF 输出的码片峰值**软值**"，
天然含相邻码片串扰（半正弦成形致码片重叠），四个值为 ±16436 / ±5328，
比率 0.324 → 相位串扰 18.1°。该串扰相位随前导固定模式（周期 32）变化，
差分跨 2 码片不能完全抵消 → 留下确定性相位偏置 0.3° → inc 偏置 ≈900。

**证据**：偏置是加性的（cfo=0 → 923；1k → 1049+923=1972 ≈ 实测 1973；10k → 10486+923
≈ 实测 11381，误差 0.25%），排除了随机性。

**影响**：修正后残留 858 Hz（对 2.4 GHz 是 0.36 ppm << 标准 ±80 ppm），
对系统功能无影响；但对"小 CFO"（≈1 kHz）场景，修正后残留与原始值同量级。

**候选方案**：
（a）cref 换成"纯码片 ±1 序列"（去掉串扰），代价是 `z` 的相干增益降低；
（b）软件标定补偿（固定减 900），但偏置随输入幅度/工作点可能变；
（c）接受 —— 对功能无影响。

**优先级**：低。

## I-6 [已定位·中] CFO 估计的触发源：前导能量检测缺失

> **结论摘要（2026-10-01，读全文前先看这里）**：本节是 5 轮探索的过程记录，最终结论三条：
> ① `preamble_sync` 判据的 `cos(ω·256)` 因子是“检出率随 CFO 非单调”的根因 → 已改为
> 复相关模（方案 C，见文末补记），自主触发 0/50 → 25/50；
> ② `cfo_est` 的对齐是（cref 索引 + 服务窗相位 + 预热 + `t==3` 补丁）的四重联合约定，
> 参数调不通 → 需重写 COLLECT 段，落成 **I-17**；
> ③ 独立检测器 `preamble_detect`（CFO 免疫、三 CFO 点 20/20）保留为观测输出，未接 `est_start`。
> 专题总览见 `docs/15` 第 5 节。

**现象**：Phase 3 集成（`rtl/rx/legacy/rx_top.sv`）尝试把 CFO 估计做成 free-running
（每 2048 采样自动启动一轮），实测**完全失败**（cfo=0 也只检出 1/20）。

**根因**：`cfo_est` 的 `cref` 参考序列要求收集窗起点与**帧起点绝对对齐**
（cref 从码片 0 开始）。free-running 周期触发下，窗口相位随帧间隔漂移
（15342 mod 2048，步长 1006，gcd=2），撞上对齐窗需要 ~1024 帧量级。
误对齐的轮次会给出垃圾估计（实测 -503873 … +504086），虽经 |inc| ≤ 450 kHz
门控仍能通过 → 消旋乱转 → 全链崩溃。

**当前方案**：`rx_top` 保留 `est_start` / `rot_load` 外部触发端口，验证期由 TB
以帧起点信息驱动。**代价**：真实系统需要自己产生这个触发。

**真实触发源候选**：
（a）**前导能量检测**：跟踪 MF 输出能量 IIR 基线，突变超阈触发；
   需标定突变点到帧起点的固定延迟，精度需 ±1 码片（8 采样）以内；
（b）用 `detect`（同步锁定，已发生在帧内）反推：需为 `cfo_est` 增加起始码片偏移
   参数，且前导只剩一半（1024 拍），收集窗需缩短；
（c）双阶段：先用上次 inc 粗消旋 → 同步能锁 → 再精估。

**优先级**：中（不影响功能验证，但上片前必须解决）。

### [2026-09-29 后续] cref 偏移参数已加，自主触发未收敛

**已实现**：
- `cfo_est` 新增 `CHIP_OFF`（cref 索引整片偏移，默认 0）与 `NSMP_P`（收集窗长，默认 2048）。
  默认值保持旧行为，**bit-true 与顶层链回归均通过**。
- `rx_top` 新增 `EST_CHIP_OFF`/`EST_NSMP` 参数与 `trig_ext` 输入（内部检测器 / 外部触发
  可切换，帧间屏蔽 + 超时兑底）。默认外部触发（已验证路径）。

**未收敛**：自主模式（trig_ext=0）实测全崩（0-1/20），即便 CHIP_OFF 试过 56/57。

**根因分析**：`cfo_est` 的对齐假设与"收集窗起点=帧起点"深度耦合，不只是 cref 索引：

1. **cref 奇偶相位**：`me_m = 2*mc_e + CHIP_OFF` 要求 CHIP_OFF 为偶数，否则偶链取到
   奇数码片对应的 cref（奇偶翻转）；而实测偏移 457/8 = 57.125 非整数片。
2. **服务窗位置**：`k0 = !t[3]` 使候选仅在 t mod 16 < 8 服务；偏移后 I 峰的窗内
   位置（实测 (3−457 mod 16)≈10）可能落在服务窗外。
3. **`t==3` 跳过补丁**：该补丁针对"start 在帧起点前"的特定相位，偏移后前提不再成立。
4. **`mc_e >= 2` 预热与 zacc 窗口**：同样隐含起点假设。

**结论**：要让自主触发工作，需要系统重推四者的联合对齐（或反之，在触发器与
`cfo_est` 之间增加一个"对齐校准器"把任意触发点映射到 cref 的规范网格上）。
**当前保持外部触发交付**；自主触发列为待办。

### [2026-09-29 再探] 改用 sync.detect 作触发源，发现相位约束

**改用 detect 的理由**：实测 DET 相对帧起点偏移 **538±1 采样**（结构决定：
`ready` 需连续 2 块 = 512 + 相位对齐），比独立检测器（±18）精确一个量级，
且复用已有硬件。已实现 detect 上升沿 + 可配延迟触发（`TRIG_DLY_N`）。

**关键发现——触发时刻存在相位约束**：

`cfo_est` 的服务窗由 `k0 = !t[3]` 决定（t mod 16 < 8 时才服务），候选 ce∈[0,7]
只在 t≡ce (mod 16) 服务。要让某个候选对上 I 峰，触发时刻的采样相位必须满足：

```
(触发点相对帧起点的相位) ≡ 1 (mod 16)   →  ce = 2/3 可对齐 I 峰
```

原设计的"帧起点 **−31**"正是为此选的（−31 ≡ 1 mod 16）。而 detect 偏移 538 的
相位是 **10**，即使加延迟调到 545（相位 1），实测仍不收敛 —— 说明除相位外还有
其他约束（cref 索引与服务点片号的精确映射）未完全弄清。

**已参数化**（默认为旧行为，回归 PASS）：`CHIP_OFF`、`NSMP_P`、`SKIP_T3`。

**教训**：`cfo_est` 的"对齐"不是单一偏移量，而是（相位 + 片索引 + 预热 + 补丁）
四者的联合约定。要开放触发点自由度，正确做法是**重写它的对齐层**，而不是
在它之外叠参数。

### [2026-09-29 C 方案] dump 内部状态反推对齐关系（仍未收敛）

**工具**：`mc_top_tb` 增加 `ESD` 事件（dump `cfo_est` 内部 `t / ce / co / mc_e[3] / mc_o[7] / me_m`）。

**实测反推**（外部触发，已知正确）：

```
服务点在帧内位置 = Δ + t          (Δ = start 相对帧起点的偏移, 实测 = 1)
cref 索引        = 2n            (n = 服务序号; 预热跳过前 2 次)
两点拟合: (位置17, me=2), (位置33, me=4)  →  位置 = 8·me + 1
对齐要求: 位置 ≈ 8·(cref码片号) + 3.5     →  (Δ + ce) mod 16 ≈ 3.5
外部验证: Δ=1, ce=0 → 1 vs 3.5 (差 2.5 采样, 由 p_hat 吸收) ✓
```

**自主触发推导**：Δ=538 → `ce = (3.5−538) mod 16 = 9.5` 超出 [0,7]。
加 3 拍延迟（Δ=541, mod16=13）→ ce ∈ [4,7] 可达；配合 `CHIP_OFF=0`、`SKIP_T3=0`、
`NSMP=1024`（避免窗伸入数据段）——**实测仍不工作**（EST 仍乱）。

**结论**：除已识别的四重约束外**仍有未识别的约束**。调参不是正确路径；
要自主触发需**重写 `cfo_est` 的 COLLECT 段**（cref 索引从触发偏移直接推导，
而非依赖固定候选结构）。

**当前交付**：外部触发（已验证）；所有 `EST_*` 参数可调，默认外部模式。

### [2026-09-29 另一路] 自相关 CFO 估计（对齐无关但有模糊）

**动机**：绕开 cref 对齐。`z[n] = y[n]·conj(y[n−256])` = |s|²·e^(jω·256)，
**窗在前导内任意位置都成立**。

**实测（ref）**：

```
对齐无关性: 起点 0→700 采样, 估计恒 +396.10 kHz (完全一致) ✓
噪声精度:   SNR +20dB std 0.12 kHz, +10dB 0.43 kHz, +5dB 0.92 kHz ✓
模糊范围:   ±31.25 kHz (= fs/(2·256)) ✗ 不足 450 kHz 需求
```

**关键负面结论**：前导所有周期结构都是 256 的倍数/因子，模糊周期彼此相关，
**无法用双延迟互解**（D=248 不是前导周期，`s[n+248]≠s[n]`，估计必错）。
**对齐无关与无模糊不可兼得**：cref 去调制无模糊但需对齐；自相关对齐无关但模糊 ±31kHz。

**适用场景**：若射频能把 CFO 限制在 ±31 kHz（2.4GHz 的 ±13ppm），自相关可独立使用；
否则只能做精修/跟踪（配合它法粗估）。

### 普遍方法调研

前导/突发检测是**任何接收机的通用问题**（用户洞察："同步探知——知道自己是同步/不同步"
是普遍需求），标准术语是 **preamble detection + lock detection**。主流方法：

- **A. 能量检测**：滑窗能量 vs 噪声基线。最简单（1 乘加/采样），但阈值对噪声
  不确定度敏感（免标定难）。
- **B. 双滑窗（DSW）**：比较前后相邻窗的**能量比**。比值判据自动适应绝对噪声水平，
  适合粗检测（802.11 的 CCA 属此类）。
- **C. 延迟自相关（Schmidl-Cox）**：`Σ r[n]·conj(r[n−D])`，D = 前导周期。
  对频偏鲁棒（差分抵消）+ 处理增益，但要求前导有周期性（OFDM 系标准做法）。
- **D. 匹配滤波相关**：与已知前导直接相关。SNR 意义最优、定时精度最高，
  但需对齐假设（N 个相位）且计算量大。
- **E. 两级检测（粗+精）**：工程最常用 —— 粗：能量/双窗→候选时刻；
  精：只对候选做相关→确认 + 精定时。
- **F. 统计检验 / 显著性（GLRT / Neyman-Pearson）**：H0（纯噪声）vs H1（信号+噪声），
  检测量 Λ = 窗能量 / 噪声功率估计，门限由1目标虚警率 P_fa 定。

**锁定检测（lock detection）的普遍做法**：M/N 计数器（N 次观测 M 次通过 → 确认锁定）、
双门限升降计数、序贯检测（SPRT）。
本项目已有对应：`preamble_sync` 的 `ready`（连续 2 块合格）即 M/N 计数器，
两阶段退锁超时即 lock-loss 检测。

### 四类检测器的实测对比（Python 参考层，2026-09-29）

统一 Neyman-Pearson 框架（均在纯噪声段标定阈值 = 相同虚警率），20 帧/点，
只改 SNR 与 CFO；括号内为定时偏移（采样）与标准差：

```
SNR  CFO    energy          dsw             autocorr        matched
+20   0    Pd=0.50(±122)   Pd=0.60(±3.8)   Pd=1.00(固定504) Pd=0.90(±3.3)
+20  10k   Pd=0.60(±112)   Pd=0.60(±3.8)   Pd=1.00(固定504) Pd=0.60(-239)
+10   0    Pd=0.60(±130)   Pd=0.50(±17)    Pd=1.00(±2)      Pd=0.90(±3.3)
+10  10k   Pd=0.60(±130)   Pd=0.50(±17)    Pd=1.00(±2)      Pd=0.60(-239)
 +5   0    Pd=0.60(±132)   Pd=0.40(±120)   Pd=1.00(±7)      Pd=0.90(±3.3)
 +5  10k   Pd=0.50(±116)   Pd=0.40(±122)   Pd=1.00(±7)      Pd=0.60(-239)
```

**三条本质差异**：
1. **处理增益**决定能否检出：能量类（无增益）Pd 仅 0.4–0.6；相关类（相干累加）0.9–1.0。
2. **CFO 免疫性**是最本质的分水岭：延迟自相关因差分（r[n]·conj(r[n−256])）
   在 0/10 kHz 下 Pd 完全相同（=1.00）；匹配滤波从 0.9 降到 0.6 且定时偏移乱跳。
3. **定时精度 vs 算量**：dsw 最准（±2.7）但 Pd 最低；autocorr 有固定结构延迟
   504 采样（= 窗填满两个前导周期，方差为 0，可标定）。

**结论：延迟自相关是最优选择，而且它正是本设计已有的机制**（`preamble_sync` 的
块间相关就是延迟 256 的共轭积）—— CFO 触发可直接复用，无需新增检测器硬件。

### 推荐实现（修订）

**短窗自相关触发**：用 L=64~128 的延迟自相关（延迟 256），响应点在前导起点后
约 320 采样（远早于锁定判定的 1024），响应延迟固定可标定：

```
Λ[n] = |Σ_{k=0}^{L-1} r[n-k]·conj(r[n-k-256])| / Σ|r[n-k]|²   > γ(P_fa)
```

- 归一化（除以窗内能量）使阀值对绝对幅度/AGC 不敏感；
- 触发后延迟固定拍数启动 `cfo_est`（需为 cref 引入起始码片偏移参数）；
- 虚警由第二级（`cfo_est` |acc| 质量门控）兜住。

**保留的旧候选**（若短窗触发不稳定）：前导能量双滑窗（B）+ 门控（已有）两级。

### 备选方案（早前设计，保留参考）

**用户的提议正确**：显著性判断就是能量检测的理论形式（Neyman-Pearson：
固定 P_fa 下最大化检测概率）。当时设计为**两级**：

1. **粗检测（双滑窗比值）**：跟踪 MF 输出能量，比较短窗（~64 采样）与
   长窗（~2048 采样）的**比值** —— 比值判据免去绝对噪声标定；
   分贝域门限由目标 P_fa 定（如 3–5σ，对应 P_fa 1e-3~1e-6）。
2. **精确认（已有）**：`cfo_est` 的 `|acc|` 质量门控 —— 只有估计可信才更新 inc。

**关键难点**：
- **定时精度**：能量突变点相对帧起点有固定延迟（MF 群延迟 + 检测延迟），
  需标定；cref 对齐要求 ±1 码片（8 采样），p_hat 的 8 候选可覆盖 ±几拍的残余。
- **虚警后界**：P_fa 不可能为 0，误触发产生的垃圾估计由第二级门控兜住。
- **低 SNR 下能量差变小**：前导与数据都是满幅，突变更弱；本场景帧间是纯噪声
gap（400 采样），差异则明显。

### [2026-10-01 补记] 方案 C 已实施：自主触发 0/50 → 25/50

## I-7 [待讨论·架构·靠后] 判决与置信度体系

**现象**：接收链里散落着一系列“判决”，每个都有自己的隐式判据、门限与偏置，
但彼此没有统一的语义与优化目标：

```
判决点                  现状判据                      作用范围
──────────────────────────────────────────────────────────
preamble_sync 锁定      lag-2 共轭积 vs ph_thresh     码片级 / 单块 (16 采样)
轴判别 (偶/奇)          偶奇 lag-2 自相关相减 (+8/-8)  前导期
cfo_est 对齐点          8 候选取 |acc| 最大            前导期 (2048 采样)
cfo_est 质量            相干因子 L1 >= 1/4 (est_ok)    前导期
rx_top 采纳             范围 ∧ 质量 ∧ (可选) 一致性      跨帧
SFD 检测                相关 vs sfd_thresh             帧级
帧有效性                FCS                            帧级
```

**待决问题**：

1. **优化目标未明确**：各判决点都在“各自择优”，但端到端目标是什么？
   - 最大化检出 Pd / 最小化虚警 Pfa / 最短锁定时间 / 最终 PER？
   - Neyman-Pearson（固定 Pfa 下最大化 Pd）是候选框架，但**各点的代价不对称**：
     一次虚警 = 白白占用一帧的估计周期（还可能污染 inc）；一次漏检 = 丢一帧数据。
2. **范畴（作用域）不清晰**：同一物理量在不同时间尺度上被复用 ——
   瞬时（单拍） / 块内 / 前导期 / 帧级 / 跨帧累积。不同尺度的**有效样本数不同**
   （即置信度不同），门限不应共用同一个数。
3. **偏置 (bias) 没有量化依据**：门限的保守/激进取舍靠试。实测例子：
   `INC_LIMIT` 450→500 kHz 改变了一整类行为；`est_ok` 门限 0.25 把
   “对齐差但无偏”的估计也拒了（CFO=450 kHz 时 0.117 > 0.07 一类）。
4. **一个量两种用途**：`cfo_est` 的 `|acc|` 同时是“选 p_hat 的依据”
   和“质量的度量”，尺度/量纲未区分；`est_ok` 又直接拿它做了门限。

**候选方向**：
- 统一为**置信度 (confidence)** 标量：各判决点输出 `(决定, 置信度)`，
  由下游按自己的代价函数消费；
- 置信度的构成 = **归一化统计量**（相干因子 / SNR 估计 / 样本数）+ **时间累积**；
- 明确优化目标建议：**固定平均虚警率下最大化检出**（NP），
  以“丢帧代价 vs 误触发代价”加权；
- 区分三个层次：**判据层**（瞬时统计量） / **决策层**（单次判决） /
  **策略层**（跨帧的采纳・撤销・重试）。

**现状**：本轮已把 `est_ok`（相干因子）作为第一个显式置信度输出，
`INC_CONFIRM` 作为第一个跨帧策略；但整体仍是零散的。

**优先级**：中（架构性，不阻塞当前功能；但拖得越久越难统一）。

结论：**调参不是正确路径**。

**目标**：重写 COLLECT 段——cref 索引从触发偏移**直接推导**，不再依赖固定候选结构；
