# 参考系与偏移：接收链的统一模型

> 本文抽象一类反复出现的设计问题：**信号处理模块需要"在某个坐标里定位"，而这个坐标
> 本身是估计出来的**。`cfo_est` 的对齐困境、SFO 的判决点调整、`despreader` 的
> 片边界假设，都是同一结构的不同实例。
> 最后更新：2026-09-29

---

## 1. 问题的统一形态

任何接收模块 M 处理输入时，隐含地使用一组约定来"解释"输入：

```
M 的参考系需求 = { T0, Φ, M, Ω }         （见 §2 定义）
```

**当上游改变了参考系（或从未提供），而 M 内部仍按旧假设解释输入 → 静默错误**。
这类 bug 的恶劣之处：**失效方式复杂**（`cfo_est` 表现为四重约束耦合），
且往往在"换触发源"这类看似局部的改动后才暴露。

---

## 2. 参考系的分量

| 分量 | 含义 | 典型精度需求 |
|---|---|---|
| **T0** | 时间原点（帧起点） | 帧级（±1 片） |
| **Φ** | 采样格相位（哪个采样是片 0） | ±4 采样 |
| **M** | 片边界对齐（整数片/半片、奇偶） | 整片 |
| **Ω** | 频率/相位基准（载波相位原点） | 常数相位（可免疫） |

**不是每个模块都需要全部分量**——这是关键（见 §3 表）。

---

## 3. 本项目的参考系依赖实测

（`grep` 各模块的对齐类输入端口）

| 模块 | 依赖 | 角色 |
|---|---|---|
| `rx_matched_filter` | — | 纯流式 |
| `preamble_detect` | — | **自给自足**（自相关，对齐无关） |
| `cfo_rot` | `load`, `phase_off` | 消费 Ω（可免疫） |
| `preamble_sync` | 输出 `detect`/`lphase` | **生产者**（唯一） |
| `cfo_est` | `start`, `CHIP_OFF`, `phase_off`, `p_hat` | **4 个依赖，最重** |
| `despreader` | `frame_start` | 消费 T0+M |
| `rx_deframer` | `frame_start`, `load` | 消费 T0 |

**结论**：参考系的生产集中在同步器，消费分散在各模块，但**接口语义不统一**
（`load`/`start`/`frame_start`/`CHIP_OFF` 都是"帧起始"的不同表达）。

## 4. 偏移 τ 的分解（与 docs/09 对接）

参考系的不确定性来自偏移 τ，按时间尺度分解：

```
τ = τ_s + τ_p + τ_c(t) + τ_n(t)
    静态    每包   累积      瞬时
    ↓       ↓      ↓         ↓
   标定    估计   环路跟踪   不可修(裕量)
```

- `τ_s` 静态：链路延迟、MF 群延迟、检测器固定延迟 → **标定常数**
- `τ_p` 每包：帧到达相位 → **每次估计（同步器产出）**
- `τ_c(t)` 累积：SFO（定时）、CFO（相位） → **累加器 + 环路**
- `τ_n(t)` 瞬时：抖动、相噪 → **不修**

**消费侧只需知道自己需要哪些分量**。

---

## 5. 设计规则

- **R1｜消费者不自带假设**：模块只消费**显式传入**的参考系，不内置"起点在哪"的约定。
  *反例*：`cfo_est` 的 `cref` 表内置了"表起点 = 帧起点"的假设。
- **R2｜精度需求显式化**：每个消费者声明自己的容差（如 `cfo_est` 需 ±4 采样 + 整片），
  供上游评估"提供的参考系是否够用"。
- **R3｜标定常数与动态量分离**：`τ_s` 类是常数（寄存器/参数），`τ_p` 类是动态量
  （每帧 latch）。混用会导致"改一处就崩"。
- **R4｜流式不可回溯 → 正向补偿**：硬件流式处理无法"回到帧起点重跑"，
  所以偏移只能**已知 + 正向补偿**，不能"事后修正"。

## 6. 案例：`cfo_est` 的对齐困境（模型解释）

**症状**：换触发源后（外部 → 自主），即便按推导调好参数仍不工作。

**模型诊断**（对照 R1–R4）：

| 规则 | `cfo_est` 的违反 |
|---|---|
| R1 | `cref` 表 + 候选结构内置"起点 = 帧起点"约定 |
| R2 | 未声明精度需求（实际是 ±4 采样 + 整片 + 奇偶） |
| R3 | `CHIP_OFF`（标定）与 `ce/µc_e`（动态）耦合在一个索引式里 |
| R4 | 收集窗必须"正向"落在前导内 → 触发越晚可用窗越短 |

**四重约束的来源**（每一条都是一个"隐含参考系假设"）：

```
① 相位约束:  k0 = !t[3]  → 服务窗相位必须 ≡ 1 (mod 16)
② 片索引:    me_m = 2·mc_e + CHIP_OFF  → 要求 CHIP_OFF 为偶数
③ 预热:      mc_e ≥ 2  → 前两次服务只填历史
④ 补丁:      t == 3 跳过 → 针对"start 在帧起点前"的特定相位
```

**实测反推的对齐关系**（`ESD` dump）：

```
服务点帧内位置 = Δ + t,  cref 索引 = 2n
两点拟合: (17, me=2), (33, me=4) → 位置 = 8·me + 1
对齐要求: (Δ + ce) mod 16 ≈ 3.5
外部触发验证: Δ=1, ce=0 → 差 2.5 采样（由 p_hat 吸收）✓
自主触发: Δ=538 → ce=9.5 超界；加延迟后 ce∈[4,7] 可达，但仍不工作
```

→ **仍有第 5 个未识别的假设**。这正说明"叠参数"注定失败：**假设是隐式的，
无法从外部穷举**。

## 7. 按模型的正确修法

**重写 `cfo_est` 的 COLLECT 段，使其从显式参考系推导**：

```
输入: 触发偏移 Δ（标定常数, 显式）
      → 每拍对应的帧内位置 = Δ + t          （已知, 无需假设）
服务: 位置 ≡ Δ_phase (mod 8) 时取一片        （无候选结构）
cref 索引: m = (Δ + t) / 8                  （直接算, 无奇偶/预热/补丁）
差分: 与 8 拍前的 z 比                       （替代原 16 采样差分）
```

**消除的假设**：候选结构（8 选 1）、CHIP_OFF 奇偶、预热 2 次、t=3 补丁。
**保留的**：`p_hat` 式的"片内相位微调"（因为 τ_p 是动态量，需每帧估计）。

## 8. 这类问题的检查清单（新模块设计用）

1. 该模块需要参考系的哪些分量（T0/Φ/M/Ω）？
2. 每个分量的精度需求是多少？（写进注释/接口）
3. 分量从哪来？（生产者是谁；若是常数，标定在哪）
4. 若上游参考系变化（换触发源/加延迟），哪些内部约定会失效？
5. 能否改为"从显式输入推导"而非"内置假设"？
