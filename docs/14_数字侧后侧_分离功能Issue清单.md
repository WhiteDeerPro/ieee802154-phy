## A 组：上层侧（"接住的活"）

### I-8 [功能·中] 旋性发现（FFT）工具化
- **背景**：RTL 里不做 FFT 的决定（docs/12 §2）；`run_cfo_fft.py` 已验证单帧 256 点 FFT 的精度（全 CFO 20/20、抖动 0、bin 7.8 kHz、无模糊 ±1 MHz）
- **目标**：把实验脚本固化成**可复用模块**：输入 (256 码片软值, 帧标记) → 输出 (phase_inc, 置信度)
- **验收**：接口契约文档（输入格式/无模糊范围/失败模式）；同一实现被上层与 Python 参考层共用
- **现状**：仅实验脚本

### I-9 [功能·中] 模式库工程化（patterns.py → 上层实现）
- **背景**：`model/upper/patterns.py` 是参考实现（match/discover/evict/observe 四动作）；docs/12 §5 明确"淘汰策略、容量规划、模式↔设备绑定留给上层真实实现"
- **目标**：确定**容量上限 / 老化与淘汰参数 / 与 MAC 的地址回填接口**
- **验收**：`docs/12` §3 的四场景（单/三设备 × two_stage/pattern）在工程实现上复现（PER 0%、加速 ≥20×）
- **现状**：参考实现可用（96% 命中、0 误配）

### I-10 [接口·中] 参数下发协议（上层 → 单元）
- **背景**：`cfo_rot.sv` 已有 `load` / `phase_inc[23:0]` / `phase_off[23:0]` 接口，但"何时发、发几次、失败重试"未定
- **目标**：定义下发时序（帧边界对齐）、编码（Q 格式）、粘贴失败（错帧/超时）的行为
- **验收**：协议文档 + 一个仿真场景（下发 → 消旋 → 解帧正确）
- **现状**：硬件接口在，协议空白

### I-11 [接口·低] "转发"的物理形态
- **背景**：docs/12 §5 ——"缓冲多大、何时触发上传、上行带宽/时延预算"未定，取决于节点固件与主机的实际接口
- **目标**：给定一种可行形态（前导缓冲 ≈ 256×2×21 bit ≈ 10.5 kbit；帧到达触发；DMA 或寄存器窗口）
- **验收**：与 I-13 的缓冲实现对齐（同一接口两端的两种视图）
- **现状**：未定

### I-12 [标定·低] 匹配分数的绝对标定
- **背景**：`PatternLibrary` 归一化相关只有 0.50–0.66（区分度够、误配 0%，但**绝对置信度**未标定）；与 I-7（判决与置信度体系）交界
- **目标**：把相关分数映射为"接受/拒绝"门限（含虚警率/漏检率的标定曲线）
- **验收**：一条门限曲线（分数 → 置信度），在既有报告数据上复核
- **现状**：无

## B 组：单元侧（RTL，"把消旋器喂饱"）

### I-13 [RTL·中] 前导码片缓冲 + 上层读出口
- **背景**：docs/12 §4 ——"需要补的：前导码片缓冲 + 一个上层可读的接口（DMA/寄存器窗口）"
- **目标**：缓冲 256 码片 × 2（I/Q）× 21 bit ≈ 10.5 kbit + 帧到达标记；提供串行/并行读口
- **验收**：`tb/` 下一个仿真用例：前导进 → 缓冲满 → 读出与模型一致
- **现状**：**已实现**（2026-10-02，`rtl/rx/frontend/preamble_buf.sv`）——
  采样级环形缓冲（窗口 3072×2×21 bit，DEPTH=4096）：帧到达沿触发快照 →
  收集 POST 后 **done 并冻结**（读口内容永不失效；clr 重新武装）→ 硬件
  线性化读口。例化于共享前端（`rx_frontend`，与 `preamble_detect` 同点位）。
  **与原始 10.5 kbit 码片级方案的偏离**：改为**采样级**（~172 kbit）——
  去交错依赖抽样相位（异常帧场景下恰不可信）；采样级是无损充分观测，
  抽取/相位选择留给上层（与 `patterns.discover` 口径一致）。
- **验证**（MC 平台，2026-10-02）：帧到达 → 缓冲抓取 → 读出 3072 采样，
  与理想参考对齐 `dump[576] ↔ 帧0 起点`（差 2 = MF 延迟）、r=**0.985**（20 dB）；
  `patterns.discover` 从缓冲内容直接 FFT 发现 CFO=**+101.6 kHz**（真值 +100.0）
  —— “检测 → 上报 → 分析”闭环打通（下发侧 `ext_inc` 已通）。
- **关联**：`docs/16` §9（异常帧上报）与 §4.3（观测上行）都依赖它；实现后即可打通
  "检测 → 上报 → 分析 → 下发"闭环（下发侧 `rx_top.ext_inc_*` 已通，见 `docs/08` I-22）

### I-14 [策略·低] 降级路径与模式切换

- **目标**：定义"何时用 pattern / 何时回落盲估"的判据（如：模式库冷启动、连续失配、无上层响应）
- **验收**：判据文档 + `run_pattern_link.py` 的退化场景验证

### I-18 [RTL·中] 同步器默认切换：A16 → Csq 转正（长期必做）

- **背景**：A16（现役 `preamble_sync.sv`）开销大（同口径 ~8.4k cells vs Csq v3b
  6,456 cells，**−23%**）；Csq 为 drop-in 候选（同名同端口，编译期替换）。
- **证据（已备，2026-10-02）**：影子对比 `diag_shadow_compare.py`——4 流 460 帧，
  交换失败仅 **3 帧且方向对称**（真打平）；边界回归 edge **94=94**、snr20 **60/60**、
  snr6 **17/60**、mixdev1 **FA 127–128 / FB 50** 全部打平。
- **验收**：① 默认 SOURCES/`rx_frontend` 例化切 Csq；② 全回归 + 影子对比复跑一致；
  ③ 更新基线文档（`docs/18/19`）与 `rtl/README.md` 状态表（Csq→现役、A16→归档候选）；
  ④ 打 tag（v1.2）。
- **风险/回退**：口径重置（历史数字以 A16 累计，切换后需重定格新基线）；回退 =
  切回 A16 文件（保留不删，改动仅限文件切换）。
- **依赖**：无，随时可做；建议切换日先复跑影子对比 + 边界回归。
- **现状**：**已完成**（v1.2 tag `463c2b5`, 2026-10-03）——① SOURCES/主 bin 切 Csq ✓；
  ② 全回归 + 影子对比 5 流 520 帧复跑 ✓；③ 文档同步 ✓（`rtl/README.md`、`docs/18/19/20`；
  补切 `rtl/filelist.f`——转正时漏掉，随本次修正）；④ tag v1.2 ✓。回退路径保留（切回 A16 文件）。

### I-19 [RTL·中] 多径均衡器 RTL 化（前导 LS + 频域 MMSE）

- **背景**：模型侧均衡链已验证（前导 LS + 频域 MMSE + 相干解扩）——深陷波
  `[1,−0.9]@0.25chip` 下 BER 0.30→0.18；**RTL 侧无均衡**（`docs/20` 覆盖矩阵 ❌）；
  多径回归已就位：模型侧 `test_multipath`、RTL 侧 `mp1` 场景（扩频硬扛 60/60）。
- **范围**：① 前导 LS 信道估计（复用 `cfo_est` 前导服务窗思路）；② 抽头→频响→MMSE
  权重（除法/倒数查表）；③ 频域均衡（或时域 FIR 近似）× 码片流；④ **相干解扩使能路径**
  （与现有非相干 |·| 并存、可配置）。
- **验收**：深陷波场景 RTL BER 改善可视（对齐模型侧 0.18 量级）；mp1/全回归不退化。
- **资源预估**：数 k cells（乘法器/存储为主）；建议随"低功耗"专题一并评估**活动因子**
  （均衡只在帧内/前导后短暂工作，天然低占空比）。
- **依赖**：无硬依赖；建议在"低功耗门控盘点"（`docs/21`）之后定实现形态。

### I-20 [RTL·中] 位段使能（bit-slice enable）—— ebuf 低 8 位段
- **背景**：同步路径（ebuf/ebf）已落 16 位（两个整 8 位段; notes §62）; 位剖面实测
  低位段 ~50% 翻转（§49）; 低 8 位"写零"模式 = 稳态"0→0"无翻转（省该段活动）。
  但**无条件的"8 位有效"在好 SNR 下崩**（§59 v16: snr20 23/60）——启用须有条件
  （低 SNR/地板区 或 permit 逻辑; **勿绑"状态好"**——§61 状态↔量化矩阵）。
- **设计形态**：手动表达段意图（拆段 + `seg_lo_en`）+ 工具自动插 ICG（将来综合）;
  须保持"加新减旧"一致性（量化前置——低 8 位写零与读出补零同口径）。
- **验收**：段活动统计（仿真）+ 回归; 若带条件策略, 附"启用条件 vs 帧成功率"曲线。
- **现状**：无（评估已完成: §49/§59/§61/§62——机制清晰, 待策略与实现）。

### I-21 [RTL·中] 面积优化三刀：sfd_detect 滑窗化 / cfo_rot 折叠+3mult / sfd 八边形化
- **背景**：全链 yosys 无映射估计 364,749→233,593（−36%，despreader TDM 基线后）；
  乘法器审计（notes §77）：真·变量乘仅剩 cfo_rot×2=8 / sfd_detect×2=14 / preamble_detect=13 /
  preamble_sync=9；sfd_detect 单件 58.7k 主因 = 每片“全窗重算”（128 路 29bit 加减树）。
- **三刀（按序）**：
  A. **sfd 滑窗化**（`wi += σ63·chip − σ0·s0`；整数精确等价；预估全链 −26k）；
  B. **cfo_rot LUT 对称折叠**（512→~65 项）+ **3-mult 复乘**（4→3 乘；预估 8.3k→~4-5k/件）；
  C. **sfd 八边形化**（sfd_E 2×29×29 + 归一化 4×16×16；门限需重标定）。
- **验收**：A/B 单元级对照（逐比特一致）+ 换装全回归 + 场景 FRMA 逐字节一致；C 另附门限重标定记录。
- **现状**：审计完成（§77）；**GitHub issue #1**（github.com/WhiteDeerPro/ieee802154-phy/issues/1）。

## D 组：发射侧

### I-17 [TX·中] 发射自修正（发端定时/相位对齐 + 闭环执行侧）
- **背景**：接收侧已建立"相位/网格/门限"自适应链（抽取网格对齐门实测：扫描 dev1 36→49/50）。
  机理链（本轮闭环）：**相位切换落点 → 抽取吞/吐 ±1 片 → 消旋累加器步数差 → 共同旋转
  18.28°×N（= CFO 每码片相位增量）→ 边缘帧判决擦边**。发端目前全为固定参数，是链路上
  唯一"不随链路状态修正"的一侧；且"发端帧起点相位"与"收端抽取网格"之间无约定，
  把一个本可消去的变量留给了接收机。
- **目标**：定义"发射自修正"的范畴与接口——
  1. **发端定时/相位对齐**：帧起点相位规范化（例如约束起点落到既定相位网格），
     与收端抽取几何形成跨端契约；
  2. **发端 IQ/DC 预补偿**：与 RX 侧 dc_block / I-Q 校正对称的发射侧自校正；
  3. **闭环执行侧**：观测器（docs/16）/I-10 下发协议的判决 → 发射参数修正的执行端。
- **验收**：一个闭环仿真场景（链路观测 → 判决 → 发端修正 → 指标改善可量化）；
  若纳入相位对齐，给出编码约束与实测收益（对照"对齐门"的收益口径：dev1 +13 帧/50）。
- **现状**：无（发射侧固定参数；范畴三条待确认收窄）。
