# RTL 资源分析（yosys 0.9 估算）+ 优化清单

> 2026-10-02。方法学：`/tmp` 副本上转 LUT 语法后 `proc+stat`（未做工艺映射/存储推断，偏保守）。
> **注意**：pbuf 等大存储若映射为 RAM 宏，实际面积会低一个量级；下列"位数"是"寄存器实现"的口径。

## 1. 存储去哪了（总计 222,816 位 ≈ 27 KB）

| 模块 | 数组 | 位数 | 占比 |
|---|---|---|---|
| **preamble_buf** | mem_i/mem_q [0:4095] × 21bit （DEPTH=4096，PRE=1024/POST=2048） | **172,032** | **77%** |
| **preamble_sync** | prevI/curI/prevQ/curQ [0:15][0:31] ×21bit ×4 组 + 各候选状态 | **~47,700** | 21% |
| preamble_detect | si/sq [0:64]（D+L+1=65）×21×2 | 2,730 | 1.2% |
| sfd_detect | si/sq [0:63] ×21×2 | 2,688 | 1.2% |
| despreader | acc/nxt [0:15]×17bit×4 + pwr | ~1,600 | 0.7% |
| 其它（fir/est/top） | — | <1,000 | <0.5% |

**结论：两大户 = pbuf 的"4096 深前导缓冲"（77%）+ preamble_sync 的"16 候选 × 32 码片历史"（21%）**，都是"设计选择"的直接结果。

**优化点（按收益排序）**：
1. `pbuf` DEPTH 4096 → 2048/1024（PRE/POST 减半）→ 直接砍 ~8 万位；
2. preamble_sync：**16 个候选的历史其实是同一码片流的不同移位** → 只存 1 份流 + 各候选索引 → 省 ~16×（约 4 万位）+ 大量 mux；
3. 大存储（pbuf）做 RAM 宏推断（真实 ASIC 流程）。

## 2. 相关器 / 匹配滤波：简化空间与必要性

- **相关器（sfd_detect 64 片、despreader 32 片、preamble 各相关）**：模板是 **±1** →
  **实现里只有加/减树，没有乘法器**（`wi = t64 ? +chip : -chip`）——**已是最简形式**，
  余下只有"进位保存/加法树结构"层面的优化（交给综合）。
- **MF（half_sine_fir）**：8 抽头 × 12bit 输入（X_W=12, Y_W=12）。
  可做：**系数对称折叠（pre-adder 省一半乘法）+ 固定系数的 CSD/移位加**。
- **"更简单方法"的必要性**：MF 提供"匹配增益"，简化即损失灵敏度（对低 SNR 段影响大）。
  **建议先在 model 侧跑"抽头数/近似方案 × PER"对照**再决定（工具现成）。

## 3. 乘法：Booth/压缩树 vs 更实用的压缩手段

- **Booth(基-4)+Wallace/CSA 树**：**一般不必手写**——ASIC 流程中综合工具（DC DesignWare）
  会自动生成 Booth+CSA 结构，手写通常在"特定小位宽/特殊常系数"才有边际收益（本项目未手写）。
  本仓库用 yosys 只是"估算"，其乘法映射非最优。
- **我们真正划算的压缩**（现状统计：`$mul` ≈ 399，集中在 preamble_sync / detect / despreader / cfo_rot / fir）：
  1. **平方器特化**：能量项全是 `x*x`（sfd/despreader/preamble）——**平方器比通用乘法省 ~50%**；
  2. **常系数乘法**（MF 的半正弦系数固定）→ **CSD / 移位加网络**；
  3. **时分复用**：`preamble_detect` 的 12 乘/采样，但**每 8 拍才用一次**（DEC=8）→ 少量乘法器复用；
  4. **位宽截短**：多数乘法精度过剩（21×21→42bit 结果），输入截到 12–16 位可省 30–50%（精度用 model 侧验证）。

## 5. 位宽压缩实验：21 位不是"冗余"，是"定点规划"（W=16 实测全灭）

- **21 位的来源**：`ACC_W = X_W + 9`——**12 位 ADC + 9 位 FIR 相干增益**。21 位承载的是
  "匹配滤波相干积累后的有效位"，不是随意选的。
- **裸改 W=21→16 实验**（只改顶层参数，其余不动）：
  | 配置 | 6dB | 20dB |
  |---|---|---|
  | W=21（基线） | 17/60 | 56/60 |
  | W=16 | **0/60** | **0/60** |
  原因：MF 输出是"高段有效"的 21 位定标，窄接宽隐式截低 16 位 → 信号整段丢失。
- **结论**：**"砍位宽" ≠ "改参数"，而要做"整链定点重规划"**（在 MF 输出后统一右移/重定标，
  各模块"小数点位"一致）——这是可做但需专门验证的工作（列为后续项）。
- **顺带改进**：`rx_chip_backend` 的截位 `rot_i[18:7]` 参数化为 `rot_i[W-3:W-14]`
  （W=21 时逐位等价，基线复现 17/56 验证无回归）。

## 6. pbuf 的定位与业界做法（回应"能转储么/基带怎么处理"）

- **我们的 pbuf = "算法辅助捕获"**：有读口 + clr（"上层读走 → 清 → 重新武装"），
  **本身就是可转储的**；触发式快照（PRE/POST），供上层 FFT 发现/相位扫描。
- **业界惯例**：常规接收链**不存原始样本**（流式处理）；"捕获缓冲（capture RAM）"属于
  调试/算法研究设施——触发式 + 小深度 + 可 DMA 转储；大缓冲只在调试模式常开。
  **pbuf 定位与此一致**；真实芯片中它会实例化为 SRAM 宏（因此"深度/位宽再压"的边际收益有限）。
- **动态范围的正确解法是 AGC 而非对数量化**：相关/能量/相干和全是线性运算，对数域需
  log-sum-exp 转换（昂贵）；通信接收机用 AGC 把幅度归一化后，线性定点即为最优。
  本项目 RTL 侧暂无 AGC——这也与"6dB 档检测困难"相关（幅度波动全压在静态门限上），
  数字 AGC 是比"对数量化"更对症的下一步。

### 附:AGC 与"6dB 门限问题"的关系（实测判定，2026-10-02）

问题:检测门限不通过（6dB 档）能否用 AGC 解决？
实测:
- 对 snr6 流波形整体 ×2（等效模拟 AGC +6dB、SNR 不变）→ **0/60**，削波 134,550/1,841,720（7.3%）；
- 原因:**原流信号已打满 12 位量程**（peak=2048、rms≈571）→ AGC 无增益空间,再放即削波。
- （注:先前"scale×2/×4"两个点是无效实验——gen_point 的 scale 只缩放噪声不缩放信号,实为"降 SNR";作废。）

判定:**AGC 不处理"门限不过"问题**——
1. 我们的检测判据 `|acc|/pwr` 是"SNR 型"（幅度自适应):AGC 同倍放大信号+噪声,比值不变;
2. 且本流幅度已满量程,AGC 连"量程利用率"这条唯一的收益路径也没有;
3. "门限不过"=SNR 要求问题 → 数字侧解（放松 γ + 加长确认已把 6dB 从 17→45;按 SNR 自适应是下一步)。
AGC 真正服务的场景是"信号远未占满量程"（远距离微弱信号 + 大动态范围前端）;本设计
检测链在 ADC 之后,量程已由前级设计定死。

## 8. 定点重规划（21bit → 14bit 功能无损，2026-10-02 实测）

**方法**：位宽压缩的关键不是"改 W"，而是"重定小数点"——
- MF 输出改为**高位对齐取位**：`y = acc[LSB_SHIFT +: Y_W]`，RX 缩位时 `LSB_SHIFT = ACC_W − W`；
- 新增 `LSB_SHIFT` 参数（默认 0 → TX/满精度行为逐位不变，W=21 基线复现验证）。

**结果（三流实测，逐项一致）**：

| W | 6dB(60) | 20dB(60) | mixdev1(200) |
|---|---|---|---|
| 21 | 17 | 56 | 78 |
| 16 | 17 | 56 | 78 |
| **14** | **17** | **56** | **78** |
| ≤13 | 0 | 0 | 0 |

- **W=14~21 功能无损**（位宽砍掉 1/3）；W≤13 全灭的原因是 `despreader` 截位
  `[W-3:W-14]` 下界为负（越界失效），**不是信息量不足**——继续下压需重规划"12bit 软值"假设。
- **收益**：全链位宽 −33% → 存储/加法器线性缩小，乘法器 21²→14² 面积约 −56%。
- **含义**：21bit 是"满精度 MF"的保守值；下游真正需要的"软值信息"只占高 12~14 位。

## 9. 存储用 8bit 块浮点（BFP）的可行性评估（2026-10-02 实测）

**实验**：前导窗 MF 复码片（256 点）→ 两种编码分别做符号间共轭积 → CFO 估计与相位散度对比：
线性 16bit vs **BFP 8bit（块 64，8 位尾数 + 块指数）**。

| SNR | 线性16 CFO | BFP8 CFO | 差 | M2M 散度(线/BFP) |
|---|---|---|---|---|
| 20dB | −24.8k | −25.1k | 0.2 kHz | 107.7° / 102.0° |
| 16dB | −24.9k | −25.0k | 0.2 kHz | 104.2° / 102.6° |
| 12dB | −24.4k | −24.8k | 0.4 kHz | 106.8° / 105.1° |
| 9dB | −24.6k | −24.9k | 0.3 kHz | 111.6° / 113.8° |
| 6dB | −24.4k | −24.7k | 0.4 kHz | 111.7° / 114.9° |

（注：CFO 绝对值有系统偏差——本测试的码片抽取未用锁后数据，方法层面待精修；
但"两种编码"的**相对差**有效：**BFP-8 对估计影响 ≤0.4 kHz / ≤3°**。）

**结论**：
1. **可行**——8bit BFP 编码/解码（出口定浮转换器）对 pbuf 典型用途（CFO 发现/相位分析）影响很小；
   转换器开销 ~几百门（移位/对齐/饱和），且只需"写一次 + 读一次"。
2. **收益**：存储 16→~9-10 位（尾数 8 + 块指数摊薄），对比 16bit 省 ~40%、对比 21bit 省 ~55%。
3. **值不值的判据**：BFP 的价值在"跨块动态范围"——
   - pbuf 若只存"当前帧前导"（幅度稳定）→ **线性 8~10 位就够**（更简单，无块逻辑）；
   - 若要"强/弱帧混存"（如远近设备、宽动态调试捕获）→ **BFP 有价值**（不牺牲弱帧软值）。
4. **出口方案**：存储 BFP + 读出侧"定浮转换器"回线性（运算侧保持线性）——架构合理、成本低。

## 10. "16 路相关器"重构方案调研（preamble_sync 面积之王）

**现状结构（已读透 291 行）**：
- 16 个候选**已经是 "2 路/拍 TDM"**（s_p16 轮转，每 16 采样服务全部 16 候选各 1 次；
  每候选每块(32 码片=256 采样)恰好被服务 32 次——时序已用到极限，**不能再深化 TDM**）；
- 真正的资源大头：**`prevI/curI/prevQ/curQ [0:15][0:31]` = 4.3 万位**（16 个候选各存
  "上一块+当前块"的 32 码片历史）+ 15k mux（16 路地址选择）。

**关键洞察**：16 个候选的历史**是同一条输入流的不同相位抽样**（相差 16 采样），
即 **16 份冗余副本** → 可用"**共享延迟线 + 每路游标**"替代。

**方案对比**：

| 方案 | 手段 | 收益 | 成本/风险 | 结论 |
|---|---|---|---|---|
| **A 共享延迟线** | 单条 ~640 采样环形缓冲（2 读 1 写寄存器堆，~2.7 万位）+ 每路游标（地址=游标+相位） | 存储 −40~70%、mux 大降 | 地址语义需 bit-true 验证（tb/preamble_sync 现成） | **推荐实施** |
| B 加深 TDM | 1 路/拍 | — | **不可行**：块需 32 服务/256 采样，1 路/拍要 512 拍 | 排除 |
| C 定时恢复替代 | 定时环+单路相关 | 最大 | 突发捕获/16 相位覆盖需全部重验（大改） | 研究项 |
| D FFT 相关 | 频域 | — | 面积不划算 | 排除 |

**推荐**：**方案 A**——把 `[0:15][0:31]` 的 16 份历史换成"单条共享延迟线 + 每候选游标
（4bit×16）"，读地址 `addr(c,m) = wr − (16·(mcnt[c]−m) + (s_p16−c) mod 16)` 逐路组合算出
（每拍只需 2 个地址 → 2 读口寄存器堆）；存储 4.3 万→~1.2~2.7 万位，且 16 路大 mux 退化为
"地址加法"。行为级等价，用 `tb/preamble_sync` cocotb 做 bit-true 回归。

（外部调研：公开资料中"共享延迟线 + TDM 相关器"是通用做法，与方案 A 一致；
网络后端降级导致检索质量一般，未引入额外方案。）

## 13. 共享延迟线"完整版"设计定稿（实施依据，2026-10-02）

**已精读的原版语义（唯一依据）**：
- 服务：每拍 2 路——`cand_e = s_p16`（偶链）、`cand_o = (s_p16+4)%16`（奇链）；
  每候选每 16 采样被服务 2 次（一偶一奇），每块=32 次服务=256 采样（与码片率吻合）。
- 每服务拍：读 `prev[cand][mcnt]` 做共轭积（step/stepI），写 `cur[cand][mcnt] <= v`。
- 块完成（mcnt==31）：mcnt 清零、bcnt+1、能量/判据量存档；
  **prev 更新 = {上一块 cur[0..30], 本拍 v}**——即"prev 块 = 最近完成的完整块"，
  cur 块 = 正在收集的块（块级差 32 码片）。
- 复位：全部归零（共享线版本中，线内容在复位后由"全零写"自然建立——**必须保留"每块首
  若干服务前"读到全零的等价行为**，这是 bit-true 的关键点之一）。

**地址映射（定稿）**：
- 共享线存"去交错后的码片流"两条：`line_e/line_q[0:1023]`（每拍写入 e_vi/o_vi）。
- 候选 c 的"正在收集块第 m 码片"（写点）对应"服务拍 t = c0(c) + 16m"，其中
  c0(c) = 该候选首次被服务的拍（偶 c0=c；奇 c0=(c-4)mod16）。
- 读点（prev 块第 m 码片）= 最近一个"完整块"在 m 处的码片：
  `addr_prev(c, m) = wr - 16*((mcnt[c] - 1 - m) mod 32) - PH(c) - 16`（以"块对齐"计），
  展开式需实现为逐路组合逻辑（每拍仅 2 路，面积小）。
- **验证清单**：① 复位后首块读零；② 块边界（mcnt==31）的 prev 更新语义；
  ③ 偶/奇两链相位差 4；④ bcnt/ready/axis_ok 与地址无关（不动）。

**实施清单（下一回合）**：
1. 写 `preamble_sync_ref.sv`（基于 §12 替身骨架 + 本节的复位/边界语义补全）；

### 附：地址公式精确推导（2026-10-02，实现依据）

**时间线**（复位后 smp_cnt 连续计数）：
- 偶候选 c 的第 m 次服务发生在 `smp_cnt = c + 16m`（c∈[0,16)）；
- 奇候选 c 的第 m 次服务发生在 `smp_cnt = ((c−4) mod 16) + 16m`；
- 每次服务收 1 个码片（偶链 = i_in/q_in；奇链 = 旋转后 q/−i）。

**结论 1（写侧）**：候选 c 的"cur 块第 m 码片"≡ 输入流里 `{smp_cnt ≡ off(c) (mod 16)}` 的
第 m 个子样本。→ **写侧不需要任何 per-candidate 存储**，共享线每拍写当前采样即可。

**结论 2（读侧）**：设当前块序号 K（已收 mcnt 个），prev 块 = 块 K−1：
```
t_now  = off(c) + 16·(32K + mcnt)
t_prev = off(c) + 16·(32(K−1) + m)
地址差 = t_now − t_prev = 16·(32 + mcnt[c] − m)
```
→ **`rd = wr − 16·(32 + mcnt[c] − m)`**（wr = smp_cnt；深度需求 16·(32+31)=1008 → 1024 够）。

**结论 3（复位等价性）**：原版复位后 prev/cur 全零；共享线在复位后"写指向全零区"即可
等价（实现时给线加"复位清零"或"地址在失效区时读零"二选一，取前者更简单）。

**结论 4（块边界）**：mcnt==31 时原版"prev ← {cur[0..30], 本拍} "——在共享线语义下
**自动成立**（因为"块 K−1"的 m=0..31 正好对应 `{cur[0..30], 本拍}` 的时刻），无需任何显式搬移。
